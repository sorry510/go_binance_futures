## 3. 历史数据与可比性

四年 UTC 区间为 2022-09-01..2026-08-31（1461 天），四个 Sep–Aug 完整年度。每币从 1,000 USDT 开始，使用当前现金的 10% 保证金、8 倍杠杆；双边各 0.05% 手续费和 5bps 滑点，并计真实历史资金费。使用项目 standard 1m 引擎：分钟收盘评估，下一分钟开盘成交；不改变外部 ±5% close eligibility gates。频率用完整日历周分母，每币至少需要 188 笔闭合交易，不取整隐藏不足。

ARM 大分钟传输曾 EOF；改用 checksum-verified public monthly execution+indicator archives，ARM 保留模板、独立修复参考和 funding 来源。已独立核对的少量 stale/empty minute/高周期价格通过日档或逐笔证据修复，不插值、不用自身分钟聚合制造参照。零活动 carry 分钟保留时间戳，但不制造价格 extrema。逐笔 quote turnover 按 price×base quantity 重算，记录 trade-ID span holes。独立官方周期之间价格相同的 volume 差异保留并报告；不强行覆写以凑一致。

下面所有当前结果均用 correction version `20261003-v2`；旧 ARM、未修复或 v1 修复结果都保留，不混用其收益作放行依据。ETH 下载超时与 XRP REST EOF 的已终止运行通过一次有界重试恢复；旧 UNI v1 价格未验证没有结果，v2 通过独立来源验证后完整回放。

## 4. 成交模型风险与适用边界

v64a2、v64b2、v65a、v65b 均存在同一 BTC 基础 v29 入场：2024-10-28 20:01 UTC，官方分钟记录 trade_count=0、quote_volume=0，但项目标准引擎仍在该分钟开盘成交。该样本的正 PnL 不视为可实现盈利。没有通过删除该笔和静态加减账本宣称修正利润；如后续修成交逻辑，必须完整重跑，不能仅把该笔净收益扣掉（后续现金与仓位路径会变化）。本次未改生产引擎。非零分钟成交量也不保证价差/订单簿深度或订单约束。

每个新策略都有 long、short、close_long、close_short；正常平仓需要 ROI eligibility 和独立信号，range 灾难止损 -12%、trend -20% 为唯一 ROI-only 例外。完整 LONG/SHORT、盈利/亏损、无确认/有确认、灾难止损、错误入场 hash 的矩阵见 v64/v65 研究记录及 expr-checks JSON。真实部署还要求 strategy_type=custom、模板赋值、hash 传播和可靠 CreateTime；本次未做这些操作。外部 profit/loss 不可随意与本研究配置混用。

## 5. 本次经验与现在可用的流程

1. 增加信号数量不等于增加净优势：单K/双K range pattern 增频，却降低净收益并扩大不稳定年度。不可为了 188 笔门槛添加事后交易。
2. 当前短窗口模拟正收益，不能替代同成本四年回放和冻结新币验证；单币贡献、融资、滑点与部署路径需分开。
3. 原始数据与总结冲突时以可重跑证据为准；checksum 只证明文件完整性，不证明所有值正确。来源修复要独立证据、版本隔离、完整重跑。
4. 用 OpenStrategyHash 保持入场家庭与平仓配套；当前 regime 不能无说明地改变已有仓位的风控。入口代码变化后必须重新生成 hash 绑定。
5. 所有策略保存在 temp_strategy/v64 和 v65，失败语法与诊断对照均保留。无新指标实现、无 SQL 写入。
6. custom-strategy 已通过两轮独立操作说明评估（各 0→1 严格改进），从 1.0.3 更新至 1.0.5；新增全量表导出、可验证修复、版本隔离、现金复利 sizing、执行分钟审计与 opening-hash binding。旧版本可恢复，trusted:false，quick_validate 与 git diff --check 通过。这是方法可用，不是策略收益已通过。

目标仍未完成，不能标记为 complete；这些失败不等于缺少权限/外部阻塞，也不意味着可以保证下一版盈利。下一轮应改变有证据的信号机制或取得更可靠执行证据，而不是继续放宽同一个 range pattern 的阈值或重复已失败版本。
