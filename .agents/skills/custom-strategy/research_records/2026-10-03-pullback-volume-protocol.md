# PV0/PV1 冻结协议

## 冻结的机制与实验边界

在观察 PV 收益前冻结。本轮是已有 v68 两小时回调恢复价格框架的近邻受控复验，不宣称发现全新交易优势。已有 212 个 portable JSON 的独立入口扫描没有找到同一规则中两根逆势小时、收盘继续回调及相邻成交额衰减的完全相同条件。v84/v91 的相邻缩量发生在顺势突破后的回测，而非第二根逆势回调。

- 基础为 AF0，保留 v29C 两个开仓及两个平仓程序；仅基础开仓的已观察 `Amount[0]>0` 检查与前轮相同。
- PV0/PV1 共用：4h EMA20/50 方向与 EMA20 斜率、ADX≥20 与同向 DI；两根闭合 1h 为逆势实体且 Close[1] 继续回调；当前小时 open 位于前小时极值以内，当前 NowPrice 重新越过该极值，最多追价 0.35ATR；ATR/price 在 0.0015–0.035；观察小时非零成交、前两小时 Qps>0；资金费率非拥挤（LONG≤0.0003 / SHORT≥-0.0003）；排除 EMA+DI 同向的 ADX≥25 强日线反向趋势。
- PV1 仅比 PV0 多一个 Boolean：`kline_1h.Qps[1] < kline_1h.Qps[2]`。这是两个相同完整小时的报价成交活跃度衰减，与对应 Amount 大小比较等价，不是当前形成小时放量的证明。
- 不增加时间窗口、深度或其他参数对照，不观察收益后修改阈值。闭合信号用 [1]/[2]；实时恢复继续使用 NowPrice 和 [0]，不修改用户的实时语义。
- 两组所有仓位统一使用 AF0 原始 v29C 平仓对象，逐字段完全相同：正常盈利≥16/28 需要市场确认；正常亏损≤-12 需要趋势/动量失败；灾难例外≤-20。外部 5/5 只是评估资格，不是自动退出。没有 OpenStrategyHash 依赖，未修改生产接收者或风险设置。
- helper 入口顺序冻结为 base LONG → supplement LONG → base SHORT → supplement SHORT。相同方向基础与补充 [1] 实体条件互斥，不同方向 4h EMA20/50 条件互斥；仍测试实际表达式可达性及匹配数。单仓导致补充族可阻塞未来基础机会，必须完整重撮合，禁止静态收益加总/删减推断反事实。

## 数据、成本与发布门槛

- UTC 2022-09-01..2026-08-31，1461 日；每币≥0.9次/周，即至少188笔；净收益为正；四个 Sep–Aug 完整年度无亏损；逐币报告 PF/回撤/年度/方向/族集中度。不得改分母、放宽门槛或只选择获利币。
- 开发 BTCUSDT/ETHUSDT/SOLUSDT/XRPUSDT；未观察收益验证 AAVEUSDT/ATOMUSDT/ETCUSDT/LINKUSDT 保持原冻结名单，完整日期资格待核查。开发失败不运行这些币的收益；已观察的扩展八币不是未见留出集。
- 与 AF0 前轮一致的不可变 canonical repaired v2 数据、backtest_engine_v7/standard_1m、初始1000/币、保证金当前现金10%、8倍、双边各0.0005费率/5bps滑点、实际资金费、外部5/5。入口在分钟收盘观察、下一分钟开盘填单。复用前轮 AF0 仅在成本、窗口、引擎、候选和每币 data hash 全部相同后成立。
- 结果完整性：逐笔 net=gross-fees+funding，年度/方向汇总、trade_count、全日历频率、源哈希及 entry/exit 非零成交分钟。订单簿与交易所数量/价格步长仍是标准引擎未覆盖限制，干净分钟活动不是成交保证。

所有四个完整 JSON（两个独立族、两个组合）立即保存在 `temp_strategy/20261003-pullback-volume/`；运行/检查/清单放研究缓存。本轮无 App 操作、配置变更、DB 写入、生产代码修改、交易启用或新增仓库测试文件。所有失败文件保留，只在全部门槛验证通过后才允许形成发布候选。
