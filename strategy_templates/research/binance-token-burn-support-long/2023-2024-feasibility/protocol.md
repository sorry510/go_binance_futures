# Protocol

1. Reuse the archived complete Binance CMS catalogId=49 2023-2024 title corpus.
2. Keep only first announcements that Binance will support or implement a protocol-level burn/supply-reduction mechanism for a token.
3. Preregister LONG because an actual supply-reduction mechanism is directionally positive to token scarcity.
4. Exclude periodic/completed burn reports, repeated BNB Auto-Burn reports, delisting/wind-down conversions, and stablecoin events.
5. Require >=8 events and >=8 unique tokens before any production eligibility or post-event return is read.
6. Do not split repeated burns of one token into independent cross-token evidence.
