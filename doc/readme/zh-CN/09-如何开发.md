# 如何开发

[返回中文 README](../../../README.md) · [安装与初始化](01-安装与初始化.md) · [English](../../../README.EN.md)

 **Go 开发、Bee、依赖安装、启动、编译、测试、打包以及 Web UI 开发**说明，并根据当前仓库的实际脚本更新命令。面向开发环境；首次部署数据库和账号配置请先阅读 [01 · 安装与初始化](01-安装与初始化.md)。

## 1. 代码结构

项目分为两个独立目录，分别构建：

| 目录 | 作用 |
| --- | --- |
| `go_binance_futures/` | Go 后端、交易逻辑、Web API、数据库同步、CLI 和前端静态产物 |
| `go_binance_futrues_new_ui/` | Vue/Vite 管理界面源码（目录名按当前项目实际拼写） |
| 后端 `controllers/`、`routers/`、`middlewares/` | API Controller、路由与登录鉴权 |
| 后端 `feature/`、`spot/`、`service/` | 合约/现货交易及业务服务 |
| 后端 `models/` | 数据库模型 |
| 后端 `conf/` | 配置示例与本地实际配置 |
| 后端 `scripts/test-go.sh` | 项目包的 Go 测试入口 |
| 后端 `static/` | Vue `pnpm build` 后同步的生产静态资源 |

以下命令假设两个项目目录位于同一个父目录下，且以相应仓库根目录为当前工作目录。

## 2. Go 后端开发

### 2.1 环境与依赖

当前后端 `go.mod` 指定 **Go 1.25.0**。先安装匹配的 Go 工具链，检查版本：

```bash
go version
go env GOPATH
```

进入后端根目录安装依赖：

```bash
go mod download
```

使用 `go mod tidy` 安装依赖；该命令还可能修改 `go.mod` / `go.sum`，因此仅在有意维护依赖时使用，不建议每次开发都执行。

### 2.2 开发配置和数据库

从示例复制配置文件：

```bash
cp conf/app.conf.example conf/app.conf
```

编辑 `conf/app.conf`，使用**本地开发数据库和测试环境账号**，避免把实际密钥提交到 Git。配置文件属于本地敏感文件，不应在日志、截图或代码审查中泄露。

首次初始化或需要迁移 Schema 时，先构建程序再执行项目指定的同步命令：

```bash
go build -o go_binance_futures .

./go_binance_futures sync db
```

- **只通过 `./go_binance_futures sync db` 做数据库结构同步**；不要依靠正常启动自动迁移。
- 迁移前确认目标数据库和当前 Schema 版本；不得在开发测试中意外连接、写入生产数据库。
- 平时修改普通 Go 业务代码时不必重复执行数据库同步；仅有对应 Schema 变更时按项目流程执行。

### 2.3 启动调试

在开发数据库和配置确认无误后：

```bash
go run .
```

也提供了可选的 Bee 开发方式：

```bash
go install github.com/beego/bee/v2@latest
bee run
```

Bee 不是本项目运行必需依赖。如提示找不到 `bee`，检查 `go env GOPATH`，并将 `$(go env GOPATH)/bin` 加入 `PATH`。Bee 的版本更新可能改变运行行为，优先使用已经验证的工具版本。

本地页面地址通常是：

```text
http://localhost:3333/zmkm/index.html
```

具体端口及前缀以 `conf/app.conf` 中 `web.port`、`web.index` 为准。

### 2.4 编译与测试

编译当前系统：

```bash
go build -o go_binance_futures .
```

执行项目测试脚本（自动跳过不属于可编译应用包的历史研究归档）：

```bash
./scripts/test-go.sh
./scripts/test-go.sh -count=5 -p=2 -timeout=120s
```

也可单独测试指定业务包：

```bash
go test ./controllers ./middlewares -count=1
go test ./service/... -count=1 -p=2
```

参数含义：`-count=5` 为重复运行测试 5 次；`-p=2` 为控制 Go 工具同时执行的包构建/测试数量；`-timeout=120s` 为单个测试二进制的超时限制。涉及交易、数据库与网络的测试需确认使用安全的测试环境。

### 2.5 打包

旧 README 提供 Windows 打包命令：

```bash
bee pack -be GOOS=windows
```

它是**历史命令参考**，并非已确认可在当前 Go/CGO/SQLite 依赖下跨平台成功编译。Windows/Linux 的发布包以项目实际 CI 与 Release 验证结果为准；不要把 Mac 本地构建结果直接当作服务器 ARM64 可用程序。

## 3. Web UI 开发（Vue）

管理界面属于独立前端项目。当前前端 `.nvmrc` 指定 Node **22.14.0**，`package.json` 要求 `pnpm >= 9`，并使用 Vite。

### 3.1 安装与启动

```bash
cd ../go_binance_futrues_new_ui
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

开发服务器地址以终端输出为准。前端 API 地址及代理配置以该项目的 Vite 配置和环境配置为准，不要直接修改生产服务器的 `conf/app.conf`。

### 3.2 检查与构建

```bash
pnpm typecheck
pnpm exec eslint src
pnpm build
```

生产构建结果在前端仓库的 `dist/` 下。确认后端目标 `static/` 只存放对应构建资源后，按目前项目的同步流程更新：

```bash
rsync -a --delete dist/ ../go_binance_futures/static/
```

**注意：** `--delete` 会删除目标 `static/` 下不在新 `dist/` 内的文件；仅在确认路径无误时执行。更新前端后应重新构建并同步产物，否则 Go 服务器仍可能提供旧页面。
