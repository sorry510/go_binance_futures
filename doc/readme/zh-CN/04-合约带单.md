#### 如何创建合约带单专用 API Key

本系统需要 **Futures Lead Trading Portfolio 专用的 API Key / API Secret**，不是普通 Main 账户 API，也不是 Spot Copy Trading API。申请步骤：

1. 在币安网站进入「合约（Futures）→ 跟单（Copy Trading）→ 我的带单（My Lead）」，先创建或选择自己的 Lead Portfolio。
2. 在对应组合中选择「API → 创建带单 API（Create Copy Trading API）」。
3. 在「编辑限制（Edit restrictions）」中添加服务器出口公网 IPv4 白名单，然后启用「Enable Futures」合约交易权限。
4. 将专用 API Key / API Secret 填入「合约带单 → 专用凭证」，加密保存。**Portfolio 名称仅是本地展示标签，可随意填写或留空，不参与账户身份确认。**

注意：每个合约带单组合最多可创建两个 API Key，只支持 USDT 合约；不要开启提币权限。系统只校验专用 Key 与已知 Main Key 字符串不同，**不进行本次跳过的真实账户身份核实**，请自己确认来源。

币安官方说明：[如何为 Futures Lead Trading Portfolio 创建 API Key](https://www.binance.com/en/support/faq/detail/2bec848b904b422197ce121d0925f20b)。

#### Lead 设置与专用凭证存储

**账户风险和自动开仓开关现在统一写入数据库的 `lead_trade_settings` 表**（Schema v26），不再使用 `BINANCE_LEAD_CONFIG_FILE` 或 `risk.json`。新表仅维护 Lead 行（`account_id=lead`）：`allow_new_opens`、单笔最大名义额、总名义额、日亏损熔断及更新时间。首次无数据时 **自动开仓默认为关闭**；数据库不可用或配置无效时拒绝新开仓。**不从历史 JSON 文件迁移**，旧文件不会被读取或删除。

Lead **API Key / API Secret** 仍采用现有的独立加密凭证文件，而不是新增数据库明文列。运行进程需要安全配置以下两项（示例路径、Key 均为占位符）：

```text
BINANCE_LEAD_CREDENTIAL_KEY=<standard-base64-of-32-random-bytes>
BINANCE_LEAD_CREDENTIAL_FILE=/private/lead/credentials.enc
# BINANCE_LEAD_AUDIT_FILE=/private/lead/operations.jsonl  （可选）
```

- `BINANCE_LEAD_CREDENTIAL_KEY` 必须是 32 字节随机密钥的标准 Base64 编码；遗失该密钥会导致已有凭证无法解密。不要放进 Git、日志或 `conf/app.conf`。
- 加密凭证路径必须位于仓库之外，采用仅本人可访问的目录和文件权限，不允许符号链接。审计文件可选，不影响普通风险配置的保存。
- **部署前必须先备份并核对目标数据库，人工执行 `./go_binance_futures sync db` 将 Schema v25 升级至 v26**；不能仅同步前端 `static`，也不能在生产运行期间擅自执行迁移。
- v26 的 `lead_trade_settings` 是新表，不修改 Main 账户原有配置、订单及仓位。风险设置在页面保存后直接持久化到数据库。旧 `risk.json` 的值需在页面中手动重新填写，不会自动迁移。
- 离线 SQLite 单测通过不能代替真实 MySQL 8 数据结构检查或币安实盘测试。

#### 只读观察器：明确选择才会连接真实 Binance

**默认不设置** `BINANCE_LEAD_OBSERVER_MODE`，Lead 私有观察器不会读取其凭证或建立私有 WS。完成独立密钥配置、Schema 检查并明确准备做**真实只读联调**后，才可在运行进程的安全环境中设置：

```text
BINANCE_LEAD_OBSERVER_MODE=read_only
```

这不是纯本地模拟：开启后新进程**真的会向 Binance 请求/续期/关闭 Lead listenKey、建立 User Data 私有 WebSocket，并读取真实账户、持仓及挂单快照**，因此要求有效的 Lead Key、权限、网络和代理。它只读检查 Ownership、更新内存镜像；**不提交/撤销订单，不修改 managed 成交账本，不解除真实交易门禁**。不要将 Testnet 的成功直接当成真实 Lead Portfolio 资格证明。

关闭观察器需从部署环境移除该变量并重启/停止对应进程；凭证轮换会停止旧观察器。观察器当前没有网页上的启停开关，也不自动证明真实 Portfolio 身份。可以通过已鉴权的 `GET /futures/lead/status`、`GET /futures/lead/metrics` 查看 `read_only_observer`、WS generation、镜像健康、审计检查及实际观测到的 REST 数据。

#### 安全手动验收与尚未开放的能力

1. **先核对部署版本和数据库**：前端 `dist` 同步 `static` 只更新网页资源；新 `/futures/lead/*` 接口和 Stage 7 只读观察器还必须部署新二进制。不要以旧服务仍在监听端口来推断升级完成。
2. **只做管理/权限测试**：打开六个 Card、切换中英、刷新；无 JWT 应拒绝 Lead API；合法 JWT 下应显示 `allow_new_opens=false`、`live_trade_authorized=false`。保存风控后检查持久状态；跨账户、非法值及尝试开启交易应拒绝。
3. **暂停测试放在最后**：`POST /futures/lead/pause` 会先设置**当前进程单向内存停止标志**，再尽力写入配置与审计；成功持久化返回 HTTP 200，**未能持久化返回 HTTP 202 和 `pause_persisted=false`**，此时重启/跨进程不保证暂停。没有网页恢复按钮。
4. **只读连接单独验收**：仅获准时才配置 `read_only` 并重启新版后端；检查 WS/快照健康、异常订单的只读巡检、账户归属与 Binance Portfolio 官方页面数据的一致性。所有只读状态均不得显示 `live_trade_authorized=true`。
5. **真实交易保持禁止**：`/start`、未经权威确认的 `/reconcile` 和不安全的凭证删除均返回 HTTP 423（若审计/存储未配置，也可能先返回安全的不可用错误）。STOP/TP Algo、动态价格过滤器、部分成交/手工减仓、跨进程重启恢复、双账户真实每 2 秒 API 负载和最小额真实开平仓必须另行完成 Gate 7-5/7-6，并取得人工明确授权。

实现方案和剩余风险见 合约自动带单 Stage 实施方案（原文引用文件当前仓库缺失：`doc/trade/币安合约自动带单-Stage实施方案.md`）；各阶段实施/代码审计记录位于 `doc/trade/`。**本功能仅供单用户自用研究和运维，不应以离线测试结果宣称已可实盘带单。**

#### Lead-01 历史阶段配置语义（以下说明不代表当前开关状态）

- 风险配置仅暴露三个用户字段：`max_order_notional_usdt`、`max_total_notional_usdt`（都必须大于 0，且单笔不超过总额），以及可选的 `max_daily_realized_loss_usdt`（`0` = 不启用额外每日亏损上限）。
- **未完成的旧 Lead 配置不再兼容、不迁移**。文件中旧 `enabled`、回撤和持仓数量字段都会被严格拒绝；如需使用，应按新结构重新保存。不会因此启用真实交易。
- `GET /futures/lead/config` 增加 `risk_configured`，表示两个必要金额上限是否合法。页面保存无效额度会明确失败，而不会假装“交易配置就绪”。
- 审计文件未配置时，**合法风险设置及加密凭证仍可保存**；如果日志可写则额外记录事件。为了防止意外开启，`/start`、`/reconcile`、实际交易 Broker 和 `LeadDurableOpenGate` 仍保持锁定。
- 页面仅保留单个灰置开仓开关；当前 Stage 不允许把它设置为 true。“暂停”仍沿用旧版**进程内单向安全锁**，并弹出确认。此阶段不接入新的策略或实盘执行。
- 独立只读观察器、Lead/Main 账户隔离、WS 运行时身份验证、订单/Fill/Ownership、API 权重预算均保留。底层多重授权与风控策略适配会在 Lead-02/03 结合主合约统一，而不是在 Lead-01 直接删掉安全检查。
