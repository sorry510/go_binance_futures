## 现货量化自动交易（06-7）

现货量化已接入原有 **2 秒策略轮询**，使用独立 Spot 币种、技术指标、`LONG → BUY` / `CLOSE_LONG → SELL` 规则；**只有原有两个业务开关**，不需要第三个模式、额外环境变量或任务中心。

**1. 配置交易环境（`conf/app.conf` 的 `[binance]`）**

| `testnet` | Spot REST | 使用的 API 凭据 | 说明 |
| --- | --- | --- | --- |
| `true` | `https://testnet.binance.vision` | `testnet_spot_api_key` / `testnet_spot_api_secret` | Spot Testnet；**不使用**合约测试网 `testnet_api_key` / `testnet_api_secret` |
| `false` | `https://api.binance.com` | `api_key` / `api_secret` | **Spot 正式网：真实资金与真实订单** |

测试网的 `testnet_binance_spot_base_url` 设置为 `https://testnet.binance.vision`，**不要追加 `/api/v3`**（由 SDK 自动拼接）。`testnet` 是既有 Binance 环境设置，修改 `app.conf` 后须**重启服务**；同时检查同一进程里其他使用此环境选项的功能。

**2. 开启自动交易**

1. **配置中心 → 现货量化交易**：打开总开关（`config.spot_quant_enable=1`）。
2. **现货量化交易 → 现货量化交易**：为币种设置报价资产预算（`usdt`）、技术指标、`long` / `close_long` 策略及止盈止损，再开启对应币种开关（`spot_symbols.spot_quant_enabled=1`）。
3. **新开仓 BUY** 需要总开关和币种开关都开启、签名用户数据 WS 已就绪、策略信号成立，并通过余额、数量精度和交易所规则校验。关闭任一开关只会停止**新的 BUY**；已有 Managed 持仓仍会继续按原止盈止损 / 平仓策略检查 **SELL**，未结算订单仍会对账。关闭开关**不会立即强制卖出**持仓，自动 SELL 仍要求已验证的 Fill 归属和可用余额。

**注意**：默认的 `profit=100`、`loss=100` 指 **+100% / −100% 无杠杆 ROI**，不是常用的 +8%/−6%。`close_long` 是达到退出 ROI 阈值后的卖出许可，**仅有规则为 true 不意味着立即平仓**；开启前核实阈值与预算。


### 现货扫描与 API 限额优化

- 调度周期仍为 **2 秒**，同一 Runner 不会并行运行多轮；实际每轮耗时取决于币种与 Binance 响应。
- 每轮优先检查有 Managed 持仓或待结算订单的币种，再顺序扫描 `spot_quant_enabled=1` 的其他币种；**没有独立的现货全局选币策略**。
- 策略所需的 Spot 24 小时行情在同一交易环境内短期缓存 **4 秒**，K 线缓存最多 **7 秒**，且不会跨最新交易所 K 线周期边界复用。相同请求合并；缓存失败不作为有效行情。
- 正式网与测试网缓存严格隔离；正式网在行情 WS 新鲜时优先采用 WS 最新价格，测试网绝不引用正式网行情。
- 所有实际 REST 请求继续经过现有 Binance API Weight 预算及 `429/418` 退避保护。缓存不能保证永远不触发限额；应在系统看板查看 Spot `USED-WEIGHT-1M` 和请求端点统计。

### 关闭开关后的运行行为与故障恢复

**关闭总开关或单币开关并不是「紧急停止全部自动下单」。** 关闭后不再发出新的 BUY，但已有由本系统 Fill 证据验证的 Managed 持仓仍可能在退出条件满足时发出 MARKET SELL；关闭本身不触发立即卖出。

- 有待平仓持仓或未完成订单时，程序仍需访问 Spot REST / 签名 User Data WS，继续进行策略退出与对账；未经过签名 WS ACK 时自动 BUY 和 SELL **均暂停**（不允许绕过 WS 直接 REST-only SELL），但已有订单可走 REST 只读对账。
- 当全部开仓开关关闭、且没有 Managed 持仓和待处理订单时，签名 WS 在下一次状态检查后停止连接/重连，后台只进行低频本地数据库检查；重新启用时恢复。
- 关闭状态下若异常订单持续返回 `ErrNeedsReview`，单币恢复尝试按 5、10、20、30 秒逐步退避（上限 30 秒），避免每 2 秒重复获取交易所数据。需要人工核实订单、Fill、仓位及 Binance 实际状态。异常解除后，最迟在下一次退避到期时重新尝试。
- 完全停止本程序发起任何自动订单需要在外部进程管理器停用交易服务，**这也会停止现有持仓的自动退出和对账**；操作前必须自行确认交易所实际仓位、未完成订单及保护措施。项目目前没有独立的 Spot Quant kill switch。
- 缓存有界（每类最多 256 个条目）并采用最近使用时间淘汰；这只优化行情 REST，不替代 Binance API weight 预算或订单恢复限速。

主网交易仍需按既有发布验收流程单独验证，离线测试成功不代表完成实盘验收。
