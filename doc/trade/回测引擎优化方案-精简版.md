# 回测引擎优化方案（精简版 · Review 修订）

> 状态：已根据 `CODE_REVIEW_回测引擎优化方案-精简版.md` 修订，待复审。只优化本地项目代码；不处理旧回测数据，不修改生产库、实盘交易流程或 `conf/app.conf`。

## 目标与原则

只解决三个问题：**存储空间更少、执行速度更快、结果更接近历史真实交易**。

- 保留 Go + MySQL + Expr，不引入 DuckDB，不重写回测系统。
- 保留 `standard_1m`（快速研究）与 `adaptive`（按需 1s/Trades 验证）。
- 复用现有 1m 月度 ZSTD、64 月**内存** LRU、Equity 压缩、ROI 静态判断和 ZIP/CSV 前向扫描；不重复实现。
- 手续费、滑点、杠杆、策略规则与资金规则保持原样；正确性修复导致结果改变时单独记录版本及原因。

## 1. 存储更少

**现状：** `service/historicalmarket/resolution_provider.go` 先从 MySQL 的 `market_klines_1s`、`market_trades` 读取稀疏缓存，覆盖不足时读取公开日级 ZIP，再把 1s/Trades 写库。ZIP 缓存属于 `public_data.go`，与 1m 的 64 月内存 LRU 是两套机制。

**改法：**
1. 继续按需获取高精度数据，绝不预加载全区间 1s/Trades。
2. 在现有 `public_data.go` ZIP 缓存上增加**跨回测复用、容量限制和过期清理**；用 `market/symbol/日期/类型` 定位，保留归档 URL、SHA256 和覆盖范围。
3. **不得直接关闭 MySQL 写入。** 先改造 `SecondBars` / `Trades` 的命中路径：优先复用既有 MySQL 行，未命中则从已校验 ZIP 按时间范围读取；只有验证文件缓存可独立命中后，才停止**新获取**的高精度明细永久写库。保留旧数据的只读兼容，不迁移、不清理。
4. `SecondCacheHits`、`TradeCacheHits`、`ArchiveCacheHits` 分别明确统计「行缓存」「文件/扫描命中」「归档命中」，避免优化前后统计口径失真。写库与不写库仅作为开发对照测试，不增加永久 UI 开关。

**验收：** 固定相同任务比较新增磁盘字节数；重复运行不能重复下载同一归档；关闭新明细写库后不会每次都回退网络；删除文件缓存后能按来源重新获取、校验哈希，来源失效则报错。

## 2. 执行更快

**现状：** `service/backtest/adaptive_engine.go` 已通过 `DetectROICandidate`、`analyzeCloseRuleROIProfile`、`ruleCanPassForROIRange` 筛选候选分钟，但规则分析按候选分钟重复执行；`BuildIntrabar` 反复聚合高周期行情与指标。标准模式已有部分安全的增量指标缓存。

**改法：**
1. **复用 `analyzeCloseRuleROIProfile`：** 回测初始化时按持仓方向预计算退出规则依赖和 ROI 阈值，候选分钟复用结果；仅在能严格证明规则不成立时跳过高精度读取。
2. **增量 Intrabar：** 1s/Trade 只推进当前 K 线；缓存已完成 `[1+]` 指标，仅重新计算依赖当前 `[0]` 的数据；先验证缓存字段一致，再复用标准模式已有优化。
3. **按需升级：** 普通分钟走 1m；存在真实触发可能才查 1s；1s 无法判定顺序或表达式时才查 Trades。保留已有 ZIP/CSV 前向扫描。
4. 使用 Go Benchmark / pprof 定位热点后，再优化临时 map、slice、重复排序及不必要的对象构造。

**验收：** 固定相同代码基线、数据、策略和硬件，分别对比冷/热缓存耗时、CPU、内存、1s/Trades 调用量；BT-2 纯性能优化必须保持交易、事件、Equity 结果一致（差异为 0）。不预设虚假的提速倍数。

## 3. 结果更贴近历史

**现状：**
- `standard_1m` 无法判断分钟内触价先后；`adaptive` 主要细化平仓，开仓仍按分钟收盘信号、下一分钟开盘成交。
- 实盘在 `feature/feature.go` 中优先使用 `feature/api/binance/mark_price_ws.go` 的**币安 Mark Price WS**，不可用时回退本地价格；回测 `service/backtest/environment.go` 用普通 K 线 Close 计算 ROI。两者价格来源、时间粒度和调度时点不一定一致。不可将两者概括为完全相同的快照价。
- `service/backtest/indicator_cache.go` 的当前 K 线缓存没有同步刷新 `TakerBuyAmount[0]` / `TakerBuyRatio[0]`。

**改法：**
1. 先修 TakerBuy 缓存缺陷；明确**实盘 Mark Price 优先/回退**与**回测普通 K 线价格**的口径差异。验证历史 Mark Price 来源可用性后，再决定是否接入；暂不新增行情订阅。若 ROI 使用 Mark Price，候选分钟筛选也必须使用一致的价格证据；否则不能用普通 K 线高低价安全地排除触发。
2. 对分钟内双阈值、同秒先后问题，按 1s、必要时按 Trades 的时间戳与 TradeID 判定；禁止凭 1m OHLC 猜测顺序，禁止未来信息泄漏。
3. 不把「1m 开仓 + 按需精细平仓」称作完整秒级实盘回放；真实循环存在约 2 秒调度及执行延迟。完整生产节奏模拟不纳入本轮。
4. 保留手续费、滑点、资金费处理；高精度证据不足时明确报告，不虚构精确结果。

**验收：** 盘点并复用 `service/backtest/engine_test.go`、`indicator_cache_test.go`、`intrabar_test.go`、`warmup_test.go`、`funding_rate_environment_test.go` 等现有用例，只补缺口：多空、同分钟双阈值、同秒歧义、资金费时点、动态 `[0]`、缓存开关和缺失证据。正确性修复的结果变化必须逐条解释。

## 开发顺序（各阶段独立 Code Review）

| 阶段 | 要做什么 | 主要代码 |
|---|---|---|
| **BT-1 准确性** | 修 TakerBuy；确认实盘/回测价格语义、ROI 候选筛选与成交时序；补必要测试 | `service/backtest/indicator_cache.go`、`environment.go`、`adaptive_engine.go` |
| **BT-2 速度** | 复用 ROI 规则分析；Intrabar 增量化；安全复用指标缓存；基准测试 | `service/backtest/adaptive_engine.go`、`environment.go`、`indicator_cache.go` |
| **BT-3 存储/IO** | 现有归档缓存加容量限制与跨运行复用；改造命中路径后减少新高精度明细写库 | `service/historicalmarket/public_data.go`、`resolution_provider.go`、`sparse_repository.go` |

### 最小放行标准

- **更省：** 比较相同任务的新增空间，不以删除旧数据充数；文件缓存命中可正常运行。
- **更快：** 上一阶段完成后重测基线；不得省略必要策略判断。
- **更准：** 非语义改造逐笔、事件及 Equity 一致；语义修复升级 `service/backtest/types.go` 中对应 `EngineVersion` / `ResolutionModel`，沿用 `AgentBacktestRun` 已有的版本、`StrategyVersion` 和 `DataHash` 字段，不新建版本系统。
- **边界：** 不运行 `sync db`，不写生产库，不调用真实交易接口；测试仅用本地/隔离数据源。代码与假数据测试通过不代表实盘或历史全量验证通过。
