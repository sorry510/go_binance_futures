## 一、前端改动范围：优先现有模块

- 优先复用现有现货币种配置区域和现有前端框架（Vue + pnpm）；在现货交易相关位置增加简洁的“策略交易” tab/区域，不在首页增加大批新菜单。
- 保留目前 `/notice/spot` 和 `/listen/spot` 页面原有通知与监听语义；不要把 `listen_symbols` 的 `short` 当成新策略卖出。
- 现货 `spot_symbols` 的启用/监听字段与“允许真实策略交易”明确分离。全局 Spot 模式 `legacy/strategy/off` 由后端安全校验，前端不能越过状态切换拒绝条件。
- 旧的新币抢购/通知入口不改造为策略交易页面，延用原入口与业务逻辑；已计划废弃的 `eatRate` 不增加 UI 兼容。
- 页面展示后端已计算的数值/状态/完整性；不在 Vue 重新拼计算法或把订单 ACK 视为持仓。

## 二、最小 UI 结构及字段

| 区域 | 必需字段/操作 | 限制 |
| --- | --- | --- |
| 顶部状态 | 当前 Spot 模式、main/auto_strategy、真实接口就绪/实盘授权状态、异常原因、行情最后更新时间 | 默认显示不能实盘；未知账户/状态不可开关 |
| 策略配置 | 币种搜索、`LONG/CLOSE_LONG` 规则/技术指标、预算（标 quote 币种）、独立启用开关 | 不展示可操作 SHORT；更新配置时保留旧字段 |
| 库存周期 | holding_id、symbol、净持仓 base 数量、quote 平均成本、当前市价、状态、剩余数量 | 同币重新买入新周期独立行 |
| 委托 | clientOrderId、Binance orderId、BUY/SELL、类型、委托量、已成量、剩余量、状态、时间、异常原因 | UNKNOWN/部分成交/撤销清晰区分 |
| 真实成交 | tradeId、orderId、成交量、价、quote 成交额、commission 与币种、实际成交时间 | 明细按需展开/分页，不全量加载 |

### 10.2 安全边界与页面实际呈现

- 策略配置的启用开关**只保存配置**，不会将全局模式从 `legacy` 切换为 `strategy`，不会绕过 S3-R1 的代码级实盘封锁。
- 页面顶部明确显示当前 Spot 模式、`main/auto_strategy` 和 **未授权实盘**；即使数据库被直接改为 `strategy`，后端 `live_approved=false` 与真实写门禁也不会开放。
- Holding 财务数据使用现有 `HoldingReport`，未核实 Fill 不能被计入已结算库存/成本/净盈亏，缺少核验或 BNB 历史费率时显示 `incomplete` 与具体原因；**不根据订单 ACK 或本地价格推算不存在的真实收益**。
- 委托查询保留 `unknown`、`reconcile_required` 状态，但不把含签名 URL、凭据或原始数据库错误透传到前端。**未成交 base 数量 = requested_qty - filled_qty（精确 Decimal）**；`reserved_qty` 对 BUY 为 quote 预留、SELL 为 base 预留，不可直接用于展示通用剩余数量。Fill 逐条保留实际 commission 和币种。
- 页面只从本地表读取行情价及更新时间，**不声称价格实时有效**；现货通知/监听、旧新币交易和合约逻辑保持原路由。
