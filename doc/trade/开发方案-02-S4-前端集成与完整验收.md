# 方案 02 · S4：现货策略交易前端、完整回归及交付验收

更新：2026-11-09
状态：**待开发/未验收**。前置：[S3 策略执行与库存风控](开发方案-02-S3-策略执行与库存风控.md)；完成后按 [方案 03 币本位 C0](开发方案-03-币本位自定义策略交易.md) 衔接。
目标：以**最少页面和接口**让用户管理现货自定义策略、查看真实订单/库存/成交/收益，完成前后端及测试库验收，并提供给 03 可复用的实现规则与测试证据。**S4 完成不自动开启实盘。**

## 一、前端改动范围：优先现有模块

- 优先复用现有现货币种配置区域和现有前端框架（Vue + pnpm）；在现货交易相关位置增加简洁的“策略交易” tab/区域，不在首页增加大批新菜单。
- 保留目前 `/notice/spot` 和 `/listen/spot` 页面原有通知与监听语义；不要把 `listen_symbols` 的 `short` 当成新策略卖出。
- 现货 `spot_symbols` 的启用/监听字段与“允许真实策略交易”明确分离。全局 Spot 模式 `legacy/strategy/off` 由后端安全校验，前端不能越过状态切换拒绝条件。
- 旧的新币抢购/通知入口不改造为策略交易页面，延用原入口与业务逻辑；已计划废弃的 `eatRate` 不增加 UI 兼容。
- 页面展示后端已计算的数值/状态/完整性；不在 Vue 重新拼计算法或把订单 ACK 视为持仓。

## 二、最小 UI 结构及字段

| 区域 | 必需字段/操作 | 限制 |
| --- | --- | --- |
| 顶部状态 | 当前 Spot 模式、main/auto_strategy、实时/Mock 状态、异常原因、行情最后更新时间 | 默认显示不能实盘；未知账户/状态不可开关 |
| 策略配置 | 币种搜索、`LONG/CLOSE_LONG` 规则/技术指标、预算（标 quote 币种）、独立启用开关 | 不展示可操作 SHORT；更新配置时保留旧字段 |
| 库存周期 | holding_id、symbol、净持仓 base 数量、quote 平均成本、当前市价、状态、剩余数量 | 同币重新买入新周期独立行 |
| 委托 | clientOrderId、Binance orderId、BUY/SELL、类型、委托量、已成量、剩余量、状态、时间、异常原因 | UNKNOWN/部分成交/撤销清晰区分 |
| 真实成交 | tradeId、orderId、成交量、价、quote 成交额、commission 与币种、实际成交时间 | 明细按需展开/分页，不全量加载 |
| 盈亏/数据完整性 | 毛盈亏/已核实净盈亏、费用资产清单、当前未实现估值、`incomplete` 原因 | 币种不一致时不显示虚假的净收益 |
| 只读处理 | 手动刷新/请求受限恢复、查看错误与日志 | 不在 S4 提供对真实订单的自由取消、接管、清仓或批量删除 |

**建议交互**：一页/一个 tab，两层明细（库存周期 → 委托 → Fill），不照搬 U 本位的复杂历史批量删除/人工状态修改。操作按钮的可用性由后端状态与权限决定，前端禁用只是提示，不构成安全边界。

## 三、API 最小契约（具体路径 S4 实施时落实）

| 路由用途 | 需要返回/接收 |
| --- | --- |
| 查询策略列表及配置 | account、owner、symbol、strategy_trade_enabled、budget_quote、quote_asset、价格新鲜度、mode |
| 修改独立策略配置 | 只允许白名单字段，校验有效 LONG/CLOSE_LONG、交易对和合理预算 |
| 读取 Spot 模式/申请切换 | 返回当前模式、禁止切换的具体原因、旧活跃订单/持仓风险；禁止前端强切 |
| 查询策略库存周期 | 分页+筛选 symbol、状态和时间；每个 holding_id 的独立汇总 |
| 查询周期的委托和 Fill | 展开时按 holding_id 取子订单，继续按订单拉真实成交 |
| 查询挂单/待恢复状态 | `unknown/reconcile_required` 等状态、最后查询时间与可诊断错误 |
| 手动刷新/恢复请求（可选） | 仅调用后端**受限的只读查单/对账**，不能绕过账户和只读门禁 |

后端必须复用项目现有 JWT/响应风格、精确 account/owner 作用域和输入校验；禁止通用的“传任何 account_id 就操作任意账户”。所有响应对外使用明确 DTO，密钥/签名/内部秘密配置不可返回，错误信息要避免暴露私有凭据。
