# 方案 02 · S4-R5：现货币种列表/配置去账户绑定

日期：2026-11-10  
状态：**源码改造与隔离单测通过；正式服务联调/部署仍未执行，S3 交易门禁继续 BLOCKED**。

## 一、问题与调整原则

原 S4 把 S3 用于订单与持仓归属的 `account_id=main`、`owner=auto_strategy` 错误地复用到普通币种列表，还在 `ListSettings` 中先读 `config.spot_auto_trade_mode`，导致配置表或模式异常时，正常的 `spot_symbols` 列表也无法访问。这不是 JOIN Account 表，而是 Controller、Service、前端请求链路不必要的业务耦合。

**改为仿照合约交易 `GET /features` 的简单查询层次：JWT 登录 → 读取 `spot_symbols` → 搜索、报价资产/启用筛选 → 数据库 COUNT 与分页 → 返回币种配置。** 查询单个币种、修改指标/策略/预算都仅依赖 `symbol`；不因交易模式、账户归属或本地仓位状态影响列表。

## 二、当前接口约定（R5 优先于历史 S4 文档）

| 接口 | 新行为 | 访问控制 |
| --- | --- | --- |
| **`GET /spots/symbols`** | 唯一新的策略币种管理列表入口；替换旧 `GET /spots/strategy/configs`（新路由中已移除）；返回 `items,total,page,limit`。支持 `symbol,status,quote_asset,page,limit`，从 `spot_symbols` 查询；quote 仅 USDT/USDC/FDUSD，页大小 1～50，按 symbol 排序 | 保留 JWT，不传也不读取 `account_id` / `owner`，不查询 `config` 交易模式表 |
| `GET /spots/strategy/config?symbol=BTCUSDT` | 单币种独立配置读取，仅从 `spot_symbols` 读取 | JWT，无 Account/Owner |
| `PUT /spots/strategy/config` | 根据 symbol 更新 `strategy_trade_enabled,strategy_budget_quote,strategy,technology` 白名单；请求仅包含 `symbol,enabled,budget_quote,strategy,technology`；严格 JSON 白名单拒绝旧 Account/Owner、mode、委托字段 | JWT，保留 LONG/CLOSE_LONG 与预算校验；**只能保存配置，不能发真实订单** |
| `GET /spots/strategy/mode` / `PUT /spots/strategy/mode` | 独立的私有交易模式状态与受限变更；不再决定币种列表是否可显示，不再负责列表的 quote filter 能力协商 | 原 `main/auto_strategy` 和资金安全门禁保留 |
| `GET /spots/strategy/holdings`、`/orders`、`/fills` | 原 S4 只读归属业务，不改 SQL、Owner 过滤、异常脱敏和 Fill 来源保护 | **仍严格限定 `main/auto_strategy`** |
| 旧 `GET /spots` | 原旧现货监听/业务使用的币种列表，未改动其业务查询和 legacy enable 语义 | 保留旧业务兼容，不与新的策略币种配置接口混用 |

新的 `Setting` DTO 只返回 `symbol,quote_asset,enabled,budget_quote,strategy,technology,last_price,last_price_at`，删除 `account_id,owner,mode,execution`。前端仅查询 `/spots/symbols`，不再把 `mode` API 当成列表前置步骤。USDT/USDC/FDUSD 筛选直接由 `GET /spots/symbols` 接收 `quote_asset` 并执行数据库过滤；不提供重复的版本或能力探测，也不尝试把新页面降级给尚未提供该路由的旧 Go 二进制。

## 三、涉及代码与冗余删除

- `service/spotstrategy/s4_read.go`：`ListSettings(ctx, db, req)` 不再接受 account/owner；删除 `ValidateScope` 和先读取 `config.spot_auto_trade_mode` 的整段 SQL/游标逻辑；仅 `spot_symbols` COUNT、查询、行数据转换。
- `service/spotstrategy/config.go`：`Setting`、`Patch` 去除无关账户/执行状态字段；`LoadSetting` 不调用 `CurrentMode`，并先检查 symbol 合法性；`UpdateSetting` 不验证 Account/Owner，仍按原白名单验证和更新。
- `controllers/spot_strategy_s4.go`：独立 `ListSymbols` 只校验 JWT 和分页参数；Holdings/Orders/Fills 仍用原来的 `s4ReadScope`。
- `controllers/spot_strategy.go`：单币种 GET 不再校验 scope，PUT 使用去账户字段后的严格 `Patch`。真实交易模式 PUT 原有校验不变。
- `routers/router.go`：删除旧策略 configs 路由，新路由 `/spots/symbols`，不复制另一套 symbol SQL；仅一个列表 Handler。
- `src/api/spotStrategy.ts` 和 `src/views/spot/trading.vue`：币种 GET/PUT 不附带 Account/Owner、不调用 mode；去掉“必须先读取 mode 4 才能展示列表”的状态机和多余横幅。按列表响应判断 quote 分页能力，保留快速 tab 切换的响应序号防竞态。
- 本地账户/受控交易页面、真实订单/仓位数据模型和 S3 实盘写门禁**未改**。

## 五、部署与安全边界

- Schema 仍为 **v25**，没有数据库迁移；未修改 `conf/app.conf`，不读取或写入生产 DB。
- S3 `spotRealOrderReleaseApproved=false`、`canAttestLiveFills=false` 不变；模式切换、自动发单和撤单仍禁用。
- 由于**删除旧 `/spots/strategy/configs` 并增加 `/spots/symbols`**，新的 Vue 产物必须和包含新路由的 Go 二进制**成套发布**。只同步静态资源到旧进程将造成 API 404；未经授权不得部署或重启服务。
- 不自动 commit/push。生产发布、实际 JWT 前后端联调、历史仓位归属、真实 Fill 来源核验及 BUY→Holding→SELL 闭环另行验收。

## 九、2026-11-10：现货列表模糊搜索与启用开关修复

### 9.1 币种查询

**根因**：原 `ListSettings` 使用 `AND symbol=?` 精确匹配，因此 `BTC` 不能查询出 `BTCUSDT`、`WBTCUSDT`。已改为 SQL 参数绑定 `symbol LIKE ?`，以 `%BTC%` 作为值，仅允许 1～32 位字母数字，输入会修剪空白并转大写；通配符、注入表达式和非法报价资产直接拒绝。筛选在 `COUNT` 和 `LIMIT/OFFSET` 前执行，并支持叠加 quote/status 条件。其他资金归属接口（Holding/Order/Fill）仍用**精确币种 ID**，不会随币种列表模糊匹配而扩展查询范围。

`src/views/spot/trading.vue` 输入框加入约 300ms 防抖自动搜索；回车/点击搜索直接刷新，清空关键字恢复完整列表。原有分页、USDT/USDC/FDUSD 页签和迟到响应保护保留。

### 9.2 启用/停用逻辑

**根因**：原 Vue `saveRow` 对开关也调用 `validateSpotTemplate`，并把未修改的 `strategy`、`technology` 一起通过 PUT 发送；这既会导致保存被旧数据格式阻断，也会使紧急停用失败。后端设计上还要求**正数 quote 预算与至少一条已启用的有效 LONG 及 CLOSE_LONG 规则**，但 UI 原来只提示通用失败。

现在开关 PUT **只传 `symbol,enabled,budget_quote`**，仅在用户修改策略/指标时才提交其 JSON。启用前展示预算和完整规则要求；预算为零、缺少规则时前端解释原因，不发送无效写请求。后端仍独立执行完整的预算、Expr 编译、LONG/CLOSE_LONG 校验，**没有放松安全条件**。停用不再校验未改动的旧规则，允许损坏草稿下的紧急停用。收到服务端成功响应后才以返回的 `enabled` 更新开关；取消、失败时保留原状态，并将已输入但未保存的预算恢复为已确认值。

**重要：表格的“启用”只是 `spot_symbols.strategy_trade_enabled` 配置，不是旧现货 `enable` 字段，更不是实盘订单授权；S3 的 `spotRealOrderReleaseApproved=false` 和 `canAttestLiveFills=false` 继续封锁真实交易。**

### 9.3 隔离测试

- 新增 `service/spotstrategy/s4_symbol_fuzzy_test.go`，覆盖 `BTC`、`btc`、单字符、前后空格、quote/status 组合、分页总数、非法 LIKE 通配符及与 Holding 精确过滤的隔离。
- 新增 `service/spotstrategy/s4_config_toggle_test.go`：最小字段启用/停用成功；缺少有效规则时禁止启用且不修改数据库；旧策略 JSON 损坏时仍可停用。
- 新增 Controller HTTP 查询测试：JWT 业务 Handler 下，模糊搜索、大小写、单字符、分页、非法输入状态均按预期响应。
- Chrome 隔离 UI 真实操作：模糊搜索与清空、预算缺失提示、规则缺失提示、有效启用/停用（仅三个允许字段）、异常 JSON 下安全停用。**256 个本地 Fixture HTTP 请求，其中只有 3 次 PUT，全部仅写本地内存，不连接币安和生产数据库**。
- Go 5 目标包、Controller、Race、`go vet`、主程序临时编译、Vue `pnpm typecheck`/`pnpm build` 均 PASS；这不是生产 JWT/真实资金 E2E。

**运行状态**：修改涉及 Go 源码与 Vue 新 `dist`，必须在停机维护窗口成套更新服务二进制与 `static`。本次没有停止正在运行的交易服务或热覆盖其静态文件；用户当前浏览器可能仍使用旧版本。
