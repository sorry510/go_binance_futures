## 1. 目标与约束

1. **个人系统优先**：单个本地交易账户、直接理解、易排查。一个全局总开关、一套币种独立启用配置、完整买卖记录即可；不设计多账户、多 Owner、提案审批工作流、特殊授权令牌、独立审计中心或双重模式状态机。
2. **以合约逻辑为模板**：复刻合约的币种管理、指标/策略配置、模板保存、定时执行、订单链路、持仓归档、账户展示和 UI 排版；只删合约独有功能，不另造第二套前端交互规范。
3. **物理表隔离**：合约订单、仓位、成交、模板表一律不与现货共用；通用技术指标计算、表格组件/弹窗、认证、日志与 Binance 行情获取可以复用函数/组件。
4. **现货只有买入和卖出**：BUY/LONG 代表开仓（持有现货），SELL/CLOSE_LONG 代表卖出本策略持有的资产；没有做空、反手、杠杆、保证金、资金费、强平、`SHORT/CLOSE_SHORT`。
5. **真实下单的必要防护不能删除**：最小余额、交易对精度/MIN_NOTIONAL、幂等 ClientOrderID、只卖本策略净持有数量、重复事件去重、失败后订单查询与恢复。它们是基本正确性，而不是复杂的控制/审计体系。
6. 不改 `app.conf`，不自行连接生产库；数据库升级仅使用项目命令 `./go_binance_futures sync db`；不自动 commit/push、不覆盖其他人未提交修改、不自动启用真实交易。

## 3. 配置中心及菜单

### 3.1 配置中心

在合约交易卡片之后新建唯一的 **「现货量化交易」** 卡片：
- 字段：**启用现货量化交易**（开/关）。
- 配置存储：`config.spot_quant_enable`，默认 `0`；独立于现有 `config.spot_enable`（原有历史字段）以及「现货抢新」和「市场监听」。
- 开启：允许扫描被单独启用的现货币种，在成功完成资金与交易校验后触发 BUY/SELL。
- 关闭：停止发起新的**自动策略**订单；已提交订单仍同步状态，原有挂单可人工撤单、仓位可人工处理；不得通过关闭配置丢失持仓记录。
- 不添加「legacy/strategy/off」模式选择、Owner、AccountID、多级实盘授权、额外开关、杠杆、保证金。
- 以保存响应确认开关状态；出错回退显示，避免前端“看起来已打开”但后端未保存。

### 3.2 顶级菜单

「合约交易」**正下方**增加独立一级菜单「现货交易」，菜单及页面保持合约同款视觉与操作：

```text
合约交易
现货交易
  ├── 现货交易            /spot-quant/symbols
  ├── 现货本地账户        /spot-quant/account
  ├── 策略模板            /spot-quant/strategy-templates
  └── 仓位与受控交易      /spot-quant/positions
币种提醒
...
```

路由名、菜单名称、图标及中英文文案与 Futures 对照维护；现货菜单不包含加杠杆、开空/平空、合约带单、资金费、强平。**保留用户已存在的合约所有菜单，不挪动合约业务数据。**

### 3.3 四个子页面

**现货交易**：直接复刻 `futures/symbol.vue` 的列表、搜索、报价币种过滤、分页、启停、预算、技术指标、策略规则、保存操作与弹窗；从现货表获取 `symbol`、`USDT/USDC/FDUSD` 报价、现价和交易精度。移除杠杆、保证金、做空字段。单币种预算使用 `spot_symbols.usdt`（单位为该币报价资产，须明确显示，如 USDC）。使用独立 `spot_quant_enabled` 表字段，不与旧 `enable` 混用。

**现货本地账户**：参照 `futures/account2.vue` 的资产、持仓、挂单三标签。资产读取币安 Spot 实际资产的 `free/locked/total`；本地持仓显示本系统买入数量、剩余数量、均价、现价、未实现/已实现 PnL；挂单显示 Binance 现货委托及本地关联。现货无 Futures PositionRisk，**本地持仓是按 BUY/SELL 成交维护的交易生命周期，不宣称等于币安全钱包余额**。账户余额读实时 Spot API，初版不另建每次余额快照表。

**策略模板**：对照合约模板管理的列表、CRUD、导入导出、指标编辑器、规则校验/试算；只有 `LONG`（BUY）和 `CLOSE_LONG`（SELL），服务端也必须拒绝 SHORT；不使用浏览器 localStorage 作为唯一持久化。模板放独立 `spot_strategy_templates` 表，不共用 `strategy_templates`。

**仓位与受控交易**：复刻现有合约页面的表格、搜索、状态、详情/子表格、手动操作外观。展示策略持仓、对应买入和卖出订单/成交、持仓数量和盈亏；允许取消**本系统**未完成订单、人工卖出**本系统**可用数量、执行简单的异常记录修复。剔除合约做空、杠杆、保证金与 AI 提案审批链。**不要做自动认领旧库存、不按总钱包余额推定策略持仓**。

## 4. 数据库设计（与合约表完全隔离）

### 4.1 只在现有表增加必要列

| 表 | 新增字段 | 用途 |
|---|---|---|
| `config` | `spot_quant_enable TINYINT DEFAULT 0` | 唯一全局现货量化开关 |
| `spot_symbols` | `spot_quant_enabled TINYINT DEFAULT 0` | 每币启用开关，避免借用历史 `enable` |

复用现有 `spot_symbols.usdt`、`technology`、`strategy`、价格、报价类型和精度；不重复增加预算/模式/Owner 等列。

### 4.2 仅四张新业务表

| 新表 | 参照合约表 | 必要字段与用途 |
|---|---|---|
| `spot_managed_positions` | `futures_managed_positions` | `id,symbol,base_asset,quote_asset,bought_qty,remaining_qty,avg_cost_quote,realized_pnl,status,created_at,updated_at,closed_at`；一行就是一次本策略 BUY→SELL 生命周期 |
| `spot_managed_orders` | `futures_managed_orders` | `id,position_id,symbol,side,order_type,client_order_id,exchange_order_id,requested_qty,filled_qty,status,created_at,updated_at`；开平订单对应并支持幂等/恢复 |
| `spot_trade_fills` | `futures_trade_fills` | `id,position_id,order_id,exchange_order_id,trade_id,symbol,side,qty,price,quote_qty,commission,commission_asset,trade_time`；去重键包括交易所订单与成交 ID，真实手续费据此算成本 |
| `spot_strategy_templates` | `strategy_templates` | `id,name,technology,strategy,create_time,update_time`；模板独立持久化 |

不新建重复的 Spot 账户、Owner、审计事件、授权 token、模式切换、归属申请或独立状态事件表。完整订单状态仍须遵循交易所 `NEW/PARTIALLY_FILLED/FILLED/CANCELED/REJECTED/EXPIRED`，不额外发明多层业务状态。金额/数量使用 `DECIMAL`，不要用 float 做资产精确结算；时间字段与项目现有一致。

**关系示意**：

```text
spot_symbols (已存在)
    └── strategy / technology / usdt / spot_quant_enabled

spot_strategy_templates (独立模板库)

spot_managed_positions.id
    └── spot_managed_orders.position_id
            └── spot_trade_fills.order_id
```

对于异步买入，在提交前持久化订单、订单关联持仓周期；一个 `client_order_id` 必须唯一；实际成交事件按交易所 `orderId + tradeId` 去重。不能用自动“余额差额”创建策略仓位。为个人单账户用途，表里**不增加多账户/Owner 业务选择维度**。

## 5. 一条最简单但完整的交易链

```text
配置中心 spot_quant_enable=1
            ↓
读取已启用的 spot_symbols（spot_quant_enabled=1）
            ↓
复用策略表达式/技术指标求值
            ↓
LONG 信号：计算报价资产预算与最小成交额
            ↓
检查交易所现货余额、交易精度、已有未完成订单
            ↓
创建本地 Spot 持仓周期和待提交订单
            ↓
通过现货 API 提交 BUY / 查询订单成交
            ↓
成交 Fill 落表 → 更新本地剩余数量、成本价
            ↓
CLOSE_LONG 信号：卖出本策略剩余数量（不超过可用 free）
            ↓
提交 Spot SELL / 查询成交和手续费
            ↓
更新持仓数量、已实现盈亏；全部卖完后标记 CLOSED
```

执行规则：
- **一个币种一个未完成策略订单**，防止同一信号重复下单；允许多个币种独立运行，无需多账户系统。
- BUY 用报价预算计算可买数量，按 `LOT_SIZE/PRICE_FILTER/MIN_NOTIONAL` 合法化；先确认 quote 资产可用。
- SELL 必须同时满足 `策略剩余持仓数量` 与 `Spot 可用余额`，绝不把账户原先持有的币当成策略盈利仓位；余额不足显示异常并停止自动卖出（不是卖掉其他现货）。
- 交易所请求超时/重启时，先用 `client_order_id` 查询已有订单再决定重试，避免重复 BUY/SELL。
- `myTrades` / 成交回报用于净持仓、成本、手续费和 PnL；手续费若用 BNB 等第三方资产，原资产记录必须保留，无法可靠折价时展示「折算待确认」，不能虚报精确收益。
- 不实现 short、leverage、margin、funding、liquidation、减仓保护单特有类型。
- 默认全局和单币种开关全 OFF；各阶段测试隔离真实 Binance 订单。

## 7. 必须明确不做的功能

- 不复活已废弃的旧方案 02 的 `legacy/strategy/off` 三态切换、`spotRealOrderReleaseApproved` 特殊审批常量、`canAttestLiveFills` 审计认证接口及旧业务建表。
- 不开发多账户、账户 Owner 切换、复杂手动 Claim/历史库存自动归属、AI 提案审批和冗长的预检状态机。
- 不共享 Futures 仓位/订单/Fill/模板数据库表；不把 Spot 假装成可以做空的 Futures。
- 不把交易记录、成交手续费、幂等和余额检查误认为“可删的复杂控制”；这些属于最小可用正确性。

## 8. 实施顺序与验收总标准

推荐按 **06-0 → 06-1 → 06-2 → 06-3 → 06-4 → 06-5 → 06-6** 执行。开发过程坚持 **先数据结构与本地计算，后订单执行，最后页面联调/实盘验证**。
