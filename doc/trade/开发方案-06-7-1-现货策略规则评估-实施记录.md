### 公开调用方式

```go
eval := line.NewSpotRuleEvaluator()

// 由后续 06-7-2 调度器读取已开启的 models.SpotSymbols
entry, err := eval.EvaluateEntry(spotSymbol)
// entry.Action == "BUY" 时，后续调度器才可能调用 Processor.ExecuteBuy

// 评估器内部执行 SpotLedger.Accounting(positionID, "")，从真实
// Fill 恢复成本和数量；调用方不能直接传入任意 Snapshot。
exit, err := eval.EvaluateExit(spotSymbol, spotLedger, positionID)
// exit.Action == "SELL" 时，后续调度器才可能调用 Processor.ExecuteSell
```

**以上 API 当前不会被 `main.go` 自动调用。** 本阶段不操作 Binance 交易所；默认环境加载 Spot 市场数据，不读取 Futures Kline、PositionRisk 或 Futures 持仓。

## 二、与现有合约交易一致的语义

1. **LONG**：按保存顺序读取已启用的 `long` 规则，第一条表达式为 true 即返回 BUY 信号与该规则 `RuleHash`；不执行 short、反手或加仓。
2. **CLOSE_LONG**：使用**已确认 Fill 的 Spot 持仓**，ROI = `(SpotNowPrice - SpotAvgEntryCost) / SpotAvgEntryCost × 100%`，**不乘杠杆**。现有 Futures `AutoStopOrder` 默认为 false；因此 `close_long` 为 true 只是允许在 `profit/loss` 阈值触及时 SELL，**不是无条件卖出**。
3. 存在启用的 `close_long` 规则时，它阻止默认 Kline 兜底退出；规则为 false 即使 ROI 达阈值也保持不卖。没有 `close_long` 规则时，继承 Futures `simpleCloseStrategy` 的 **ROI ±3% 中性区与 5m Kline 确认**，但 Kline 来自 Spot，而且行情失败时**不执行 SELL**。
4. `Position` 对外只提供经过 Spot Fill 核实的 `Symbol`、`Side=LONG`、`Amount`、`EntryPrice`、`MarkPrice`、`UnrealizedProfit`、`CreateTime`；`Positions` 只包含本策略仓位（开仓时空列表），绝不读取 Binance 人工钱包或 Futures PositionRisk。
5. **已知的第三资产手续费（如 BNB）尚未折价**，不能认定为完整净收益；但是若 Ledger 确认 Fee 资产、已成交数量与持仓归属，允许根据未杠杆化价格变化计算退出信号，不会仅因未能折算 BNB 费用而把仓位永远锁死。对 `ErrNeedsReview` 或未知手续费等真正不完整成交状态仍然停用信号。
6. `OpenStrategyHash` **继续禁止**，因为现有 Spot 表尚未持久化开仓规则 hash；不能拿当前已编辑的规则作为历史 hash 冒充。06-7-2 若确实需要这一变量，必须先论证最小持久化方式，不自行增加多账户、审计或 Owner 表。

## 三、失败时禁止自动买卖

- DB ticker 时间超过 5 分钟、将来时间戳、价格为 0/NaN/Inf；低价高价/Open 无效，即使 WS 最后成交价新鲜，旧的 24h OHLC 也不能用于触发。
- 技术指标参数不完整、配置无效、必要 Kline 缺失、最近 Spot Kline 过期，或表达式类型错误/运行异常。
- 缺少真实 Spot 持仓、已 CLOSED、剩余数量为 0、均价无效、币种不一致或 Ledger 财务投影不可信。
- `short`、`close_short`、合约杠杆/资金费字段、未持久化的开仓规则 hash。
- 不根据仅有交易所订单 ACK 而认定有真实成交，不将判断出的 BUY/SELL 信号等同于实际委托成交。
