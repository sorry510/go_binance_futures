# 币安合约自动带单 — Stage 4-5 开发计划：暂停、熔断与故障保护

> 状态：**离线实现完成；等待 Stage 4-6 全链路验收**；设计与进度更新：2026-10-10。本文保留 Stage 4-5 开发规格，实际交付与测试详见 [Stage 4-5 实施记录](币安合约自动带单-Stage4-5-实施记录.md)。
>
> 前置：Stage 4-1～4-4 已有离线实现/审计。无生产 Lead 实盘授权，无自动任务、无真实撤单或解锁 `pendingReconcile`。
>
> 目标：在不复制策略、不更改 Main 交易语义的前提下，把 Lead 的“是否允许开仓”“是否能够安全处理受控退出”“是否必须等待权威对账”拆成**可观测、可测试、默认拒绝**的状态和故障行为。

## 一、开发任务

| 任务 | 开发内容 | 必须满足的约束 |
|---|---|---|
| **4-5-1** | Lead 账户运行状态机及原因码 | 状态和原因按 `account_id` 隔离；线程安全；默认 `disabled`；不添加生产开仓授权/恢复接口 |
| **4-5-2** | 暂停开仓与独立退出门禁 | `paused` 禁新开仓但不禁止经过安全核验的受控平仓、TP/SL、查单/对账；账户不可确认时不得盲写 |
| **4-5-3** | 风控熔断与故障分级 | 复用 4-2 风控证据，不重复计算盈亏；区分单次 skip、持续 trip、需持久化对账阻塞 |
| **4-5-4** | 故障事件、告警与敏感信息清理 | Lead 专属告警原因、严重度、状态变更，去重/限频、测试注入通知函数；不曝光密钥或原始签名请求 |
| **4-5-5** | 恢复条件与 Mock 回归 | 每类状态按同账户新鲜完整证据判断；恢复开仓仍要求 Stage 7 明示授权，`reconcile_required` 本阶段不允许解除；验证 Main 不受影响 |

## 二、状态定义与优先级

| 运行状态 | 触发条件（示例） | 新开仓 | 安全退出/对账 |
|---|---|---|---|
| `disabled` | 未配置/未授权/主动禁用 | 禁止 | 若已有受控仓位，允许只读识别与安全处置流程，不自动强平 |
| `paused` | 用户显式暂停新开仓 | 禁止 | 继续策略退出评估与受控仓位管理，写操作仍经账户真实性和交易所规则检查 |
| `open_ready` | 所有实时条件均满足的**模型/Mock 状态** | 仍须 Stage 7 生产授权 | 按原交易逻辑，照常独立核验 |
| `risk_tripped` | 当日亏损/回撤达到阈值，或需要人工关注的持久风险 | 禁止 | 保留安全退出/对账；不能因单次循环恢复数值而偷偷复位 |
| `reconcile_required` | unknown/超时提交、挂单/Algo 累计成交不确定或本地订单状态不一致 | 禁止 | 只读查单/诊断继续；无权威证明不得再次写订单 |
| `account_unavailable` | Key/Portfolio 真实性、余额/仓位完整性、私有 WS 健康等核心证据不可用 | 禁止 | 不确定的写操作禁止；允许只读调查、告警和后续人工安全处置 |

一个账户可同时有多条阻断原因，**不要仅用单一枚举丢失原因**。聚合展示优先级建议：`account_unavailable` → `reconcile_required` → `risk_tripped` → `disabled` / `paused` → `open_ready`。`open_ready` 仅代表模型观察，不是实盘授权；真实订单仍被只读 Broker 锁定。

## 三、故障分类与动作

| 事件 | 判定 | 行为 |
|---|---|---|
| 无交易信号、普通筛选跳过、单笔不符精度/币种白名单 | `skip`，可记录原因 | 不提交该笔；不把正常无候选升级为账户级熔断 |
| 单笔保证金不足、单笔/总敞口超限、持仓数量限制 | `skip` 或持续风险约束 | 禁新开仓，记录具体规则；持续且不可自动纠正时保留阻断原因；不改变已有 TP/SL |
| 日净已实现亏损/最大回撤达到熔断线 | `risk_tripped` | 保持停止新开仓；UTC 换日不能仅凭时钟变化自动复位，须当日完整账户快照及明确策略 |
| Lead 身份不符、凭证变化、Portfolio 归属未确认、余额/挂单/持仓快照过期 | `account_unavailable` | 禁止新开仓；可能不安全的退出写操作也拒绝并报警 |
| Binance 429/418、超时、网络中断、WS 不健康 | `account_unavailable` 或 `reconcile_required` | 依是否可能已提交订单分类；未确认提交严禁盲重试，不影响 Main 私有循环 |
| 订单提交未知、部分成交后取消、Algo FINISHED 但缺实际成交证据 | `reconcile_required` | 阻断新的修改请求；只读恢复与证据展示；不得“重置 pending” |
| TP/SL 保护单提交/恢复失败 | 需升级的高优先级故障 | 告警并暴露需要人工处理的受控仓位，不用自动市价全部平仓替代 |

故障阈值使用项目现有的 `RiskLimits` 和 Binance 429/418 限制规则，**不凭空增加固定金额或连续失败次数**。一个请求的超时不等于订单被拒；对外错误只暴露固定原因码。

## 四、关键安全不变量

1. **新开仓门禁和安全退出门禁分离**：`paused` / 日亏损熔断不能直接把持仓退出的信号检测关掉；但退出写操作必须继续遵守 `min(managed_qty,live_qty)`、Lead 专属账户和过滤器，故障时不盲写。
2. **不引入生产激活捷径**：不得因为添加状态机而给 `RiskController`、`LeadExecutionAdapter` 增加无权威依据的公共 `Enable` / `Resume` / `ResetPending`；保持 `ReadOnlyOrderBroker` 禁止所有下单/撤单。
3. **账户和锁隔离**：Lead 状态、告警、阈值、冷却、连接健康独立于 Main，不直接修改全局 `FutureEnable`、Main 缓存、主账户 Ownership。
4. **告警不等于放行**：记录/通知失败不能自动解除原阻断。引入事件接口时必须处理重复报警、敏感信息脱敏和来源归属。
5. **Stage 5 边界**：Stage 4-5 开发状态判断和模拟告警；不实现生产 User Data WS 生命周期、持久化重启对账、跨进程 claim、真实撤单或 per-key API 调度。这里应留下明确且 fail-closed 的接口契约，而非伪装 Stage 5 已完成。

## 五、建议代码落点（开始开发时核对）

- `service/leadaccount/`：独立状态机（建议 `state.go`）、故障分类（建议 `fault.go`）、通知接口与对应 `*_test.go`；已有 `risk.go`、`executor.go`、`close.go`、`recovery.go` 只作必要的接口对接。
- `feature/account_trade_cycle.go` / `feature/feature.go`：不改变 Main Runner；Lead 预开仓检查保留明确错误/原因码；确保退出评估仍可运行。
- 优先复用 `feature/api/binance/market_data_guard.go` 的 429/418 事件语义和现有 `notify` 出口，但不能触碰 Main 全局告警状态或泄露签名请求。
- 不需新增策略模板、用户路由或数据库迁移；如确需持久化事件，先记录 Stage 5/6 扩展需求，未经明确授权不写业务数据库。

## 六、验收测试（Stage 4-5 完成条件）

| 场景 | 预期 |
|---|---|
| 默认状态/未授权/配置不完整 | 0 次 Lead 新订单，0 次生产写请求 |
| 主动暂停后出现 LONG/SHORT | 双方向均不得新开仓；Main 原流程不变 |
| 暂停状态下已有受控仓位触发 TP/SL | 策略退出仍被评估；只有持仓和 API 数据可信时才允许安全处置 |
| 日亏损/回撤达到阈值 | 持续阻断开仓；不能被新一轮循环覆盖 |
| WS 过期、余额/持仓快照缺失 | `account_unavailable`，原因与告警明确，禁止不确定写 |
| 下单超时/Algo 状态不确定 | `reconcile_required` 持续存在，反复循环与并发调用不重试 |
| 仅得到一条终态订单查询结果 | 不能自行解除 pending；Stage 5 仍需完整 Ownership + 仓位对账 |
| 告警失败/重复故障 | 风控阻断不丢失；重复告警去重，关键故障可升级 |
| Lead 故障与 Main 并发 | 只改变 Lead 状态；Main 策略/订单路径完全独立 |
| Race、Vet、Build、默认拒绝及恢复边界 | 全部通过；没有实时 Lead 激活入口 |

**Gate 4-5：离线实现及定向测试完成，最终跨模块 Gate 4 仍待 Stage 4-6**。状态转换有固定原因码、故障分级可追踪且 Main 隔离；暂停不丢失受控退出信号；未知单/账户不可确认时 fail-closed。没有真实授权/生产告警/WS/重启恢复接线。
