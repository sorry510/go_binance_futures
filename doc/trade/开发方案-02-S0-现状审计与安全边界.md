## 1. 本阶段目标和边界

建立完整的现货账户写订单路径清单，识别现有持仓/挂单退出职责，确定新旧自动交易的互斥模式、币种/报价资产限制以及 S1 必须守住的不变量。

- 当前只有一个 Spot API Key，计划先支持 `market=SPOT, account_id=main, owner=auto_strategy`；未来增加账户前需要重新设计凭据映射，**绝不静默回退 main**。
- `spot_symbols` 是行情/精度与现有策略字段来源；`listen_symbols` 已实现现货 expr **通知**，不是自动买卖。
- 不运行生产 SQL DML、不查询或修改实盘账户余额和订单（除非用户另行明确授权只读查询），不动 `conf/app.conf`。
- **原有交易的安全退出优先**：如果旧自动订单仍活动或已有需管理的库存，不能单纯切换开关就停掉其卖出/退出职责。

## 3. 启用模式与账户安全决定（S1 的输入）

### 3.1 模式语义

规划单一主账户的现货**自动交易模式**：`legacy` / `strategy` / `off`，不与现有 `SpotSymbols.Enable`、`ListenCoinEnable` 或 API Key 有无混淆。

- `legacy`：保持已有自动下单入口默认行为，但不执行新策略交易。
- `strategy`：仅允许新策略自动下单；旧自动入口必须经统一门禁阻断**新风险**。如果仍保留的旧自动功能承担仓位退出职责，先拒绝模式切换，不可简单停掉退出程序。
- `off`：禁止自动增加风险；已经存在的真实资产与待处理委托仍须可查询、对账并由用户人工处理。
- 监听通知可继续运行，不受交易模式限制；手动下单/API 入口若存在须单独划定行为，不能误当成自动策略。

### 3.2 必须在切换前掌握的信息

1. 旧程序尚未成交/部分成交订单与撤单状态、持有币种、可确认的归属与卖出职责；
2. 新策略币种的 `free/locked` 余额、交易所全部未完成现货订单，哪些能可靠与本程序订单相匹配。未核实不能承诺“可安全切换”。
3. 交易所规则：`SPOT` 权限、交易对状态、`LOT_SIZE`/`MARKET_LOT_SIZE`、`MIN_NOTIONAL`/`NOTIONAL`、`PRICE_FILTER` 及 `baseAsset/quoteAsset`；价格来源和刷新时效。
4. 现有代码的日志/报警/REST 限流和只读门控是否覆盖所有 Spot 写调用；若存在绕过门禁的直连，S1 必须封口。
5. 主进程是否可能多实例并发；未来 S1 必须做到数据库事务/唯一键兜底，而不是只依赖内存锁。

**账本不能物理区分同一种可替代币的来源。** 策略归属只是本系统有真实 Fill 依据的数量上限，不足以证明手动余额绝对未被触碰；引入独立余额上限、未完成单预留、外部余额变化停单和账户级互斥。无法判断时 `fail-closed`，不为“自动化”牺牲现有资产安全。
