## 3. 现有 Spot 的数据与业务边界

1. `models/spot_symbols.go` 已包含 `symbol`、`type`、`close`、`tickSize`、`stepSize`、`usdt`、`technology`、`strategy`、`enable` 等字段；暂不需要重复新建币种表。报价资产区分（如 USDT、USDC、FDUSD）必须从真实币种信息确认，不得仅靠符号后缀假定预算币种。
2. 旧 `/spots`、`/spots/:id`、`/spots/enable/:flag`、`/spots/batch` 仍在 `controllers/spot.go` 和路由内使用。旧 `spot_symbols.enable` 保留原用途，06-1 新增 `spot_quant_enabled`，默认 0，独立控制策略。
3. `models.Config.SpotEnable` 对应现存 `spot_enable`，另有 `SpotNewEnable`、`NoticeCoinEnable`、`ListenCoinEnable`；新总开关不得复用或修改这些历史开关。
4. `spot/spot.go` 的 `TryRush`、`NoticeAndAutoOrder`、`ListenCoin`、`UpdateSymbolsTradePrecision` 已经服务于抢新、提醒、行情监听等旧业务。新量化必须有独立循环，不直接改写既有触发路径。
5. `spot/api/binance/index.go` 已有 Spot SDK 行情、ExchangeInfo、账户、Buy/Sell 下单及查单调用；仅可复用必要底层 API。当前下单函数以 `float64` 数量/价格传参，06-4 必须检查其精度、ClientOrderID、查询恢复与实时余额逻辑；不能认为现有封装已经满足新策略安全要求。
6. 现有 `controllers/spot.go` 的 `BatchEdit` 使用字符串拼接构造部分 SQL；新 `/spot-quant` API 不复制这一写法，应采用明确字段白名单与参数化更新。
7. 当前 `models/futures_trade_fill.go` 特别说明成交金额字符串需要按 SQL 的 DECIMAL 处理，而不能直接让 ORM 将其变成 VARCHAR；Spot Fill 也应以精确十进制保存，不能使用 float 金额结算。
