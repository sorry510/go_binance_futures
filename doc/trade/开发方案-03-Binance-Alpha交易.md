# 方案 03：Binance Alpha 交易（个人版）

状态：设计稿；**先确认官方 API 能否完成真实交易**，再决定要不要开发。
优先级：P2。若官方交易接口不可用，就不做 Alpha 自动下单。
范围：Binance Alpha/Alpha 2.0，不是普通现货交易对；只采用官方公开接口。

## 1. 目前可以确认什么

- Binance 官方开发者目录已有独立 Alpha Trading 产品；官方连接器提供 Token List、Ticker、Klines、Depth、Market Trades 等**公开行情能力**。
- 公开行情 API 可以做币种列表和自定义策略信号，**不能凭此认定普通 API Key 也支持 Alpha 下单、查单、查个人成交和撤单**。
- 本地项目没有 Alpha 的正式交易下单/持仓归属实现；不能直接复用 Spot 下单接口冒充 Alpha 订单。
- Alpha 交易对与 Spot 同名 Token 不能仅按字符串合并，至少使用 Alpha 官方 tokenId / symbol 标识。

参考：[Alpha 官方 API 目录](https://developers.binance.com/en/docs/catalog/advanced-trading-alpha-trading/api/rest-api)、[官方 Alpha SDK](https://pkg.go.dev/github.com/binance/binance-connector-go/clients/alpha/src/restapi)。

## 2. 开发顺序：最多三步

### A1：一天内先做接口能力核对，而不是先写系统

列出并核实官方文档、当前 API Key/账户权限是否支持：
1. 下单（买、卖）；
2. 查订单和实际成交数量/费用；
3. 查询可用余额与已购买资产；
4. 撤单/订单超时后恢复查询。

四项缺一项，**自动交易功能暂缓**，无需规划复杂交易后台。不调用网页隐藏接口、Cookie 或第三方私有网关。

若没有可验证的个人自动下单能力：任务到此停止，记录“不支持”，避免无效开发。用户若只需要看 Alpha 行情，可以单独做只读观察功能。

### A2：最小行情与自定义规则（可选）

如确实需要行情/策略预览：
- 简单 `alpha_symbols` 本地表（Token ID、symbol、价格、交易状态、更新时间），与 `spot_symbols` 分开。
- 用官方公开行情接口补价格/K线，复用现有 WS/REST 限流和自定义策略解析。
- 前端只增加 Alpha tab：币种搜索、行情、策略信号、数据更新时间。
- 默认只读、不下单，不做链上全网扫描、Alpha 评分引擎、自动跨链兑换或长期全量数据仓库。

### A3：若 A1 通过，再接最小真实交易

- 写一个独立 `AlphaOrderAdapter`，只包含买、卖、查单、成交、撤单、余额；市场键固定 alpha。
- 复用方案 01 的成交表与订单成功口径：ACK 是已提交，有真实成交才修改策略归属资产。
- 首期只支持自定义买入/退出策略、单币单仓、固定小预算和最大滑点；不做做空、杠杆、跨链路由、复杂套利。
- 手工持有的资产不能自动划给 Alpha 策略，未知订单先查单，不能盲重发。
- 先 mock/官方允许的测试环境验证，再由用户决定是否开启小额交易。

## 3. 验收与不做的事

验收：
- 正确区分 Alpha 与普通 Spot；行情数据缺失或陈旧时不发交易。
- API 权限不足时明确显示不可交易，不需要用户反复手动排障。
- 如上线真实 Alpha：交易所订单与成交/费用能查证、部分成交不会重复计账、资产不会超卖。

不做：逆向私有 App 接口、长期维护独立 Alpha 系统、抓全网链上数据、跨链钱包和手续费优化器、专用风险引擎或新的一整套交易账本。

**实施判定：若 A1 未通过，就将 Alpha 真实交易标记为 blocked，先完成方案 01/02/04；不要让 Alpha 拖慢本项目核心开发。**
