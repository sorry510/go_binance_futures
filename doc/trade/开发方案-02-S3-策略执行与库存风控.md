本阶段目标：形成**自定义信号 → 真实 Binance 委托链路 → 签名 REST 逐笔成交 → 策略库存周期 → 安全卖出 → 收益完整性**的可测试闭环。**代码实现真实 Binance API，但未通过安全 Gate 前禁止执行实盘下单/撤单。**

## 一、严格支持的信号

| 策略规则 | 交易意图 | 必须具备的条件 |
| --- | --- | --- |
| `long` | BUY，首次建立库存周期 | 无活跃持仓周期/未结订单；预算、过滤器与账户均有效 |
| `close_long` | SELL，退出已有策略库存 | 有完整归属的 holding_id 和可卖净量 |
| `short` | **禁止作为交易信号** | 现货不借币做空；监听模块的 short 只是价格下跌通知 |
| 其它规则 | 不支持，配置校验拒绝 | 不自动更改用户原策略方向 |

- 配置来自 `spot_symbols.strategy/technology`，用 `InitSpotParseEnv` 的现货市场变量、现货 K 线与指标；不可读 `futures_positions`、FundingRate 或 Futures 账户 ROI。
- 采用已闭合 K 线时间、稳定 strategy_hash、account/owner/symbol/intent 生成可持久化 `signal_key`；连续每 2s 触发不能无上限重复委托。
- 简单首版：每币同账户同 Owner 同时最多一个策略库存周期；未完成/unknown/reconcile_required 订单期间不增加新风险。**不做主动加仓、网格、马丁**。
- Spot 现有抢新/通知功能保留，但 S1 的全局自动交易模式限制旧新自动订单并行；计划弃用的 `eatRate` 不纳入开发/兼容重构。

## 二、BUY 的完整执行顺序

1. 检查 `account_id=main,owner=auto_strategy`、全局模式 `strategy`、该币策略启用、独立实盘许可（默认关闭且后端强制核验）。
2. 校验行情新鲜、官方交易对为 `TRADING`、base/quote 资产、价位和最小/最大数量、`LOT_SIZE/MARKET_LOT_SIZE`、`PRICE_FILTER`、`MIN_NOTIONAL/NOTIONAL`。
3. 预算以该交易对 **quote 币种** 表示，不默认为 USDT；扣除 quote 余额已冻结/本系统预留及估算费用/滑点后计算可请求 base 数量，按交易所 `stepSize` 保守向下取整。
4. 事务锁 `account+symbol` 稳定对象、核实旧订单/余额/活跃库存/同 signal_key；先落 `spot_strategy_orders` 的预留及唯一 ClientOrderID，再允许 经授权的 S2 真实委托提交。
5. 委托 ACK 只是“已受理”；实际每一笔 BUY Fill 才按真实数量、实际价格、手续费资产更新 `spot_strategy_holdings`。仅在首笔真实 BUY Fill 时建立库存周期并关联订单。
6. 预留尚未成交的预算按订单真实累计成交与终态释放；不能因被撤销的余量而误增加库存或重新开出同一条信号的第二单。

**测试用例**：BUY 10 → 成交 2@100 + 2@120 → 取消未成交 6。库存名义实买 4（如手续费在 base 扣，则库存小于 4）；价量加权成交价格 110，不因撤单发生变化。

## 三、SELL 与归属数量

- 只有经过真实 Fill 建立并对账完整的 `holding_id` 才允许自动 SELL。手工持有、旧抢新、未知 Owner 或其他账户的库存不得自动认领。
- 与 Binance 查询的 `free/locked` 余额交叉验证，扣除现有本策略未完成卖单的待执行数量；交易所存在无法确认的外部挂单/余额变化时停止自动卖出，并报警而不是猜归属。
- 可卖 base 上限 = `max(0,min(策略净 owned_qty − 本策略待卖数量, 实际账户可供此策略使用的 free))`。向下取精度，低于最小允许成交数量/金额的 dust 记录下来，**不超精度强行卖掉**。
- SELL 先进行数据库预留，后调用 S2 的真实 Spot 委托；同币两次 CLOSE 信号并发最多只产生一个生效预留，不能并卖两倍。
- 只有实际 SELL Fill 才减少 holding；卖单部分成交仍为 `active`，取消只释放余量；委托已结束但 Fill/余额缺口仍标 `reconcile_required`，不假定已清仓。
- 净归属量归零、关联 SELL 的成交记录与交易所余额/订单状态可信时，将本轮 holding 标 `closed`；再次买入建立**新的 holding_id**，不能混进旧周期。
- 本期不增加策略“卖出所有账户余额”的选项；无法区分同一种币的物理来源时，以已归属净量作逻辑上限，并对外部交易变化 fail-closed。

## 四、精确库存、成本及收益口径

| 项目 | 计算/展示规则 |
| --- | --- |
| BUY 净库存 | `SUM(BUY.fill.qty) − SUM(BUY.base_asset_commission)`，仅从本周期已核实成交取得；其他资产的手续费不直接扣 base |
| SELL 净库存 | 从策略净 base 量扣除真实卖出数量；若额外以 base 扣手续费也须按实际费用减量，且不可与已成交 base 数量双算 |
| 持仓成本 | 从 BUY Fill 的实际 quote 付出、数量及 quote 手续费（若有）计算本周期可分摊成本；部分 SELL 按一致的**移动加权平均成本**结转 |
| 毛已实现 PnL | `SELL 实际 quote 收入 − 被售 base 数量对应的 quote 成本`；BNB/base 手续费另列，不能直接和 quote 资产相减 |
| 已核实净 PnL | 仅同资产可直接加减；跨 base/BNB/quote 费用要有当时可核实换算来源，否则隐藏“已核实净收益”，显示 `incomplete` + 分币费用 |
| 未实现收益 | 基于剩余净归属库存的可靠实时 Spot price 估算，明确“估算”；价格缺失/过期不能展示伪精确收益 |

**关键约束**：数量和费用采用精确 Decimal/原始字符串保存，不因 float64/显示四舍五入改变真实结算。base 手续费、卖出时 base 实际扣费和 quote 手续费分别覆盖永久单测。市场报价若为 USDC、FDUSD 等不能硬编码成 USDT。

## 五、风险控制与异常行为

| 风险 | 必须处理 |
| --- | --- |
| 旧自动交易同时运行 | S1 后端模式互斥；策略开启时老功能不允许新增风险，旧库存退出责任未结清则拒绝切换 |
| 订单重复/并发 | `signal_key` 唯一、订单预留事务、单 symbol 同时最多一个活动订单 |
| 行情/交易规格失效 | 停新买卖并记录理由，不以旧价格填单 |
| 余额不足/挂单占用 | 将 free 与归属净库存、真实锁定量、待单预留同时纳入限制 |
| 未知下单/DB 错误 | S2 保留 ClientOrderID，UNKNOWN/reconcile_required 不发新订单；报警 + 允许受控只读恢复 |
| REST 429/418/超时 | 使用现有节流和有限重试，避免每 2s 持续下单 |
| 手动变更资产 | 如真实余额不足或外部委托无法分类，只能暂停策略自动交易，不能转卖其它资产 |
| 跨账户/跨市场 | 明确 account+owner+symbol 关联，不允许读 futures/coinm 仓位来补 Spot 策略库存 |

## 六、最低测试矩阵

1. 无策略、禁用策略、`short`/未知规则、账户不合法：**没有任何真实下单请求**。
2. BUY 10 实成 4 撤 6，holding 净量正确；base/quote/BNB 扣费各验证一次。
3. SELL 4 实成 1，余 3 仍 active；剩余 3 成交后 closed；下一轮同币 BUY 必须新 holding_id。
4. 同 K 线重复信号 100 次、两个 goroutine 同时触发，最多一个生效委托且无双倍预算占用。
5. 手工余额大于策略库存、其它 Owner 余额、外部挂单未知：不会以账户全部 free 创建 SELL。
6. free 小于策略 ownedQty、minimum notional 导致 dust：不超卖、合法地保留 dust/人工处理提示。
7. 没有实时价格、精度错误、无报价资产、REST 429、UNKNOWN、DB 故障：不产生新风险；原恢复逻辑仍可运行。
8. Spot 老通知、抢新、当前 U 本位交易相关回归不变；计划废弃的 `eatRate` 不纳入功能测试。

用户明确取消以 Mock 为产品功能的开发路径，S3 改为**直接实现真实 Binance Spot 交易后端代码**。本次调整只改变代码开发目标，不表示授权用实盘资产测试或取消安全门禁：

1. **真实交易适配**：采用既有 Binance SDK 的签名 POST/DELETE/GET；ClientOrderID 与信号先持久化后提交，禁止旧调用方绕过账户/模式/币种/归属审核。真实请求必须经**独立默认关闭的后端许可**，不是靠前端开关。
2. **真实业务结算**：只以签名 `myTrades` 对应的订单、trade ID、成交价、数量、手续费币种更新独立 Holding 周期；不把 ACK、订单累计量或模拟成交当作实盘已验证 Fill。不能证明实际来源时保持 `incomplete`，不计算“已核实收益”。
3. **安全卖出**：必须有 Holding 所有权证据、可卖净库存、足够 free、无不明外部挂单，以及必要的行情、合规过滤器；不得卖账户其他来源资产。未知结果冻结，不猜测也不自动重发。

5. **简化原则**：不额外开发“模拟交易业务菜单/调度/库存”，不增加庞大 Broker 抽象。已有 S2 Fake 测试可保留作为安全回归，但它们不是 S3 的最终产品架构。

### 9.2 交易结算边界

- **BUY**：只有真实签名 `myTrades` 及 `rest_verified=1` 的对应 Fill 才能创建 Holding。Base 手续费扣净库存，quote 手续费增加成本；BNB 手续费独立保留，不转换为 USDT。BUY 订单 ACK 不建库存。
- **SELL**：仅凭 `spot_strategy_holdings` 表中数字不够，必须从其已关联的全部 verified BUY/SELL Fill **重新构造归属净量且精确相等**，同时保证 real free 不低于当前 owned，且无未知外部挂单。未满足交易所最小数量/金额的 dust 留在原 Holding，不用其他手动资产“补足”。
- **部分成交/撤单**：只按实际成交数量增减 Holding；取消剩余委托不能撤销历史 Fill。待执行订单独占 `pending_slot`，同一 K 线信号不可重新生成第二笔。
- **完整周期**：SELL 净归属量零且订单已获可信终态时将 Holding 标记 `closed`，释放 `active_slot`；下一轮 BUY 必须是另一个 Holding ID。历史终态出现异常仍按 S2 R1 冻结，不自动释放风险状态。
- **收益**：只有完全证实并可同币结算的收益才展示已核实净值；存在 BNB 等第三费用且缺历史换算来源时，显示成本/毛收益/费用分币与 `incomplete`，不展示虚假净收益。未实现估值需可靠现货价格。
- **跨币**：账户 `USDT/USDC/FDUSD` quote 按真实 `exchangeInfo` 检查，不预设所有订单以 USDT 计价。
