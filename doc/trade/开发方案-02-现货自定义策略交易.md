更新：2026-11-10

范围：Binance 普通现货；`main/auto_strategy` 是**内部策略库存/委托的归属标签（防误卖手动余额）**，不是前端账户选择或币种配置绑定。现货币种列表和策略配置不传 Account/Owner；策略只支持 `LONG` 买入和 `CLOSE_LONG` 卖出。
衔接：本方案 S4 的隔离端到端测试和生产 Gate 验收通过后进入 [方案 03 币本位](开发方案-03-币本位自定义策略交易.md) 的 C0；两者数据和生产 Gate 独立。

## 一、目标与固定原则

实现 **自定义表达式 → 安全订单 → 成交核对 → 策略库存 → 卖出 → 历史与收益展示** 的完整现货量化交易闭环。

- **个人使用、最小实现**：复用现有现货 K 线/价格 WS、技术指标与 expr 评估方式、REST 代理/限流和通知；不建统一 Broker、消息队列、综合资产会计系统或新的 WebSocket 基础设施。
- **三个独立最小对象**：计划新增 `spot_strategy_holdings`、`spot_strategy_orders`、`spot_strategy_fills`（表结构由 S1 最终确认）。**不直接复用**现有 USDM 专属 `futures_managed_*` 或 `futures_trade_fills` 的持仓/结算实现。
- **持仓归属安全**：本系统只依据可验证真实 Fill 累计策略净库存，卖出最多取策略净归属量与实际可用 free 的可验证较小值；不卖手动/旧策略库存，不用报价或订单 ACK 虚构利润。
- **现货模式隔离**：保留的旧现货自动交易与新策略自动交易采用 `legacy/strategy/off` 模式互斥；旧仓位/挂单仍须安全处理。现有监听 `short` 是**下跌通知**，不能映射为现货 `CLOSE_LONG`。
- **全部默认安全**：新策略每币独立启用开关默认 OFF，真实下单另外受后端实盘许可保护；不自动启用生产下单、不自动操作真实 Binance 账户。
- **明确废弃功能**：用户计划废弃 `eatRate`，方案 02 **不开发、不兼容改造、不测试其交易业务**；仅在未来开启新现货实盘前确认旧任务已关闭，避免同一 API Key 交易冲突。
- **先本地后实盘**：方案 01 的本地成交规则是参考，其生产 G1～G6 仍待授权验证。方案 02 的开发可在本地开展，但不能当作已具备生产发布条件。

## 三、最低不可突破的验收边界

1. BUY 10、实际成交 4 后撤单 6，库存只能增加真实成交的**净** base 数量；再 SELL 1，不能将其余用户余额一起卖掉。
2. 同一个 `trade_id` 多次 REST 回放/程序重启只保存一次；同币新一轮 BUY 创建新 `holding_id`。
3. `ACK/NEW` 不算成交，取消不抹掉实际 Fill；提交 UNKNOWN 按**原 clientOrderId 查询**，不得盲目重发。
4. `base/quote/BNB` 手续费分资产记录，缺换算依据不得显示虚假的已核实净收益。
5. **资金与订单执行阶段**：未知内部归属、未核实 free/locked、过期价格、旧活动委托、异常 DB/REST 均停止新增风险。**此规则不作用于币种列表或模板/策略配置查询**，不能因为交易模式异常阻止普通币种显示。
6. 已有现货监听/抢新/通知及 U 本位功能不应因本地开发回退；计划废弃的 `eatRate` 不在本方案开发。
7. 新交易独立开关默认 OFF，S0～S4 通过**不等于**有权执行生产 `sync db`、部署、重启、下单或撤单。

### CODE_REVIEW_02-ALL 安全精简与分层结论（2026-11-10）

整体审计指出的 **“不要账户绑定”应按用途分层实施**：普通现货币种管理、模板、账户页面入参不绑定 Account/Owner；只有资金相关订单、Fill、库存 SQL 保留服务器内部固定 `main/auto_strategy` 归属。这是为了避免出售手动/旧自动库存，并非开发多账户路由。不可据此擅自删除表结构中的归属键、幂等约束、Fill 认证或实际下单门禁。

账户页面取消 `GET /spots/strategy/mode` 前置请求与 `contract_version=4` 门槛；查询 Holding/订单/Fill 时不再由浏览器传固定范围，由服务端校验 JWT 并使用固定内部范围，显式的非法 Account/Owner 覆盖仍返回 400。旧 `InspectLegacySpotRisk` 预检标记 `//go:build spot_legacy_doctor`，不参与正常 Go 构建；保留 `go test -tags spot_legacy_doctor ./service/spotstrategy -run '^TestS3Preflight'` 的只读审计测试，不提供线上医生/自动放行入口。

**尚未达成**：真实响应级 Fill 认证、持久化授权审计、旧交易库存对账、生产成套发布/回滚、BUY→Holding→SELL→PnL 真实业务 E2E；因此方案 02 **没有完成**，方案 03 依赖真实交易证据的 C0 仍不得放行。完整逐项决定与证据见 [02ALL 独立复审](CODE_REVIEW_02-ALL-rereview.md)。
