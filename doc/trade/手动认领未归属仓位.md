# 合约仓位手动认领（仅主账户）

## 功能
在“AI 受控交易 → 合约仓位 / 订单归属 → 账户仓位归属”中，`owner=unmanaged` 且仓位数量大于零的行显示“手动修复”按钮。

点击后可选择：
- `auto_strategy`：自动策略；
- `new_coin_rush`：合约抢新；
- `funding_rate`：资金费率自动下单。

`notice_auto_order` 和 `agent_trade` 不开放通用手动认领：它们还依赖提醒配置、保护单或交易提案等业务上下文，简单增加归属会使仓位看似受管、实际未能按原模块逻辑退出。

弹窗可设置目标归属、可管理数量（可小于账户真实数量）、修复原因（至少 5 个字符）。操作前会再次确认。此操作**只调整本地归属数据库，不向 Binance 发送下单、撤单或平仓请求**。但是归属生效后对应模块可能在下一轮根据现有策略条件自动平仓。

## 后端安全约束
- 接口 `POST /agents/trade/ownership/manual-claim`，沿用 JWT 登录校验，操作者从已验证令牌取得，不能由浏览器指定。
- 只支持 `main` 账户，不能触及 Lead 账户。
- 请求必须携带浏览器显示的预期账户数量；后端使用 `GetPositionFreshContext` 重新获取 Binance 账户仓位。数量不一致、仓位不存在、数量越界、NaN/Inf 均拒绝。
- 使用 ownership 公共互斥锁与数据库事务，拒绝同账户同合约同方向已有 active/suspended/reconcile_required 的归属，以及任何仍未终结的 managed 订单。
- 可重新激活旧 `closed` 且 `managed_qty=0` 的历史行，保留在审计表的原 owner/status/qty，不自动认领其他币或方向。
- 新记录的 `source_ref` 标记为 `manual_repair:<audit_id>`；资金费率归属使用 `funding_rate:manual_repair:<audit_id>`，确保满足现有退出循环的来源过滤。
- 归属更改和不可变操作审计在**同一事务**内完成。审计包括操作人、原因、交易所账户数量、认领数量、原 owner/status/qty、时间。
- 只读接口 `GET /agents/trade/ownership` 中 `manual_adjustments` 提供最近 100 条记录；前端“手动修复记录”查看。

## 数据库升级
新增 `futures_ownership_adjustments` 表，数据库架构版本从 19 提升为 20。**只允许执行项目标准升级命令 `./go_binance_futures sync db`**；不运行自动数据库写入，不直接改 `app.conf`。

部署顺序：先保留数据库备份 → 停止旧服务/按维护流程升级程序 → 运行官方 `sync db` 迁移 → 启动新服务和更新过的前端静态文件 → 核对新表及页面。当前开发过程没有执行生产迁移。

## 人工测试
1. 未归属仓位：测试 0、负数、非数值、超过账户数量、空原因等，应拒绝；合法部分数量应成功。
2. 有未决订单/已有 owner：必须拒绝，不能把同一笔仓位重复认领。
3. 页面刷新后检查 owner、可管理数量与 `manual_repair` 来源；最近操作记录必须可见。
4. 原状态为 `closed/0` 的旧归属，确认可重新激活并保留前状态审计。
5. 认领后**可能立即触发策略退出**；最好在隔离环境用模拟持仓/伪造交易所数据完成此场景测试，生产手动修复必须先确认历史真实成交。

## R2 复审后补充安全约束
- **入场价必须严格大于零且有限**：从 Fresh Binance 仓位取得的 `entry_price` 若为 0、负数、NaN、Inf 或近乎零，拒绝认领，防止收益率失真触发异常平仓；不得使用标记价替代真实入场价。
- **交易所同币种同方向只允许一行**：若 Fresh 响应重复匹配 `symbol + position_side`，拒绝认领，不再把数量累加、入场价取最后一行。
- **错误原因固定**：`manual_claim_position_not_found`、`manual_claim_account_quantity_changed`、`manual_claim_duplicate_exchange_position`、`manual_claim_invalid_entry_price`。内部错误仅记日志，接口返回 `manual_claim_rejected`，避免暴露数据库/交易所内部信息。
- **请求体上限**：本接口在解析前检查请求体不得超过 4096 字节，操作人必须取自经过 JWT 验证的用户名，不使用可伪造的浏览器字段。
- **确认风险**：前端增加明确说明——保存后可能在下一交易周期立即触发自动市价平仓。未加入“延迟退出一个周期”，因为会改变真实交易风控逻辑。
- 手动修复记录当前只显示最近 100 条。分页与时间筛选暂缓，后续有足够审计量时再增加。
- WS/REST 全量快照目前已有 2 秒的时钟偏差缓冲，**不是完全统一时间基准**。更大的时钟漂移风险仍需监控；归属状态变化的自动外部告警尚未实现。
