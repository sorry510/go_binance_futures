# 方案 03：币本位永续自定义策略交易（个人版，独立方案）

更新：2026-11-09
状态：**规划，尚未开发**。紧接现货方案 02 完成本地 S4 后开发，数据/验收独立。当前代码与 go_bn_test Schema v25（由 02 S1 升级）。
范围：只支持币安 COIN-M 永续合约（如 `BTCUSD_PERP`），不做交割合约和跨币自动划转。
目标：**自定义策略 → 按张下单 → DAPI 查单/真实成交 → 独立受管理持仓周期 → 反向结算币种盈亏 → 订单明细**。

## 一、现状与取舍

- `feature/api/binance/delivery.go` 当前主要提供 DAPI 账户、`exchangeInfo` 和公开行情 WS；**没有完整的下单、查单、撤单、逐笔成交、持仓恢复链路**。
- `feature/delivery.go` 当前只有同步币种/精度的基础逻辑；`main.go` 内币本位精度更新与公开行情 WS 仍被注释；不可宣称已经有稳定运行的交易行情管线。
- `delivery_symbols` 有杠杆/保证金模式及策略字段，但缺可靠的 `contractSize`、`contractType`、`marginAsset` 交易规格快照；实施前必须核实官方交易所字段与真实交易对状态。
- `service/futuresownership`、`futures_trade_fills` 的实现以 USDM 账户、数量与结算语义为前提。**只借鉴其幂等/恢复设计，不直接把 COINM 塞入 USDM 数据表**。
- **不建统一 Broker**，只做一组 COIN-M DAPI 薄调用 + 极简策略执行器 + 三张独立最小表。既有 U 本位逻辑保持原样。

## 二、首版严格业务边界

- 一期只有主账户 `main`、唯一自动策略 Owner `auto_strategy`；DAPI 私有请求显式携带账户作用域，验证对应凭据可用，任何未知账户拒绝，绝不回落为 main。
- 只支持币本位**永续、单向持仓 One-way** 的自定义 `LONG`、`SHORT`、`CLOSE_LONG`、`CLOSE_SHORT`。若账户为 Hedge Mode，**停单并提示**；不自动切换、不自动双向开仓。后续如有需要另评审与方案 04（U 本位双向持仓）的边界；币本位首版坚持 One-way。
- 每个币种独立启用/交易预算开关，默认 OFF；不因 `delivery_symbols.enable`（行情/监控启用）自动允许下单。
- 下单单位为**合约张数**，必须取官方 `contractSize` 及 LOT_SIZE、市场状态、保证金币种、价格精度、风险限制；缺任一关键信息不得开新仓。
- 不套用 `USDT/price×leverage` 数量公式；下单数量与已持张数在数据库和前端明确标识为 contracts，不得与 base 币或 USD 名义价值混用。
- 初期尊重 Binance 账户已有杠杆、保证金模式及仓位模式；不自动切换配置，不主动处理额外用户手动/外部仓位；归属不明时禁止自动平仓。
- 先以 REST 订单/成交/持仓查询进行状态恢复；公开行情 WS 必须确认稳定后才可用于价格，旧代码注释状态不能视作在线。若后续需 DAPI User Data WS，单独增加，不在首版硬建新通用 WS 框架。
- 与 USDM、Spot 的开关、资金、订单、日志、仓位归属严格分离。已确认异常时只补查/报错，不盲目重复委托。

## 三、最小记录结构（预计 3 张新表）

| 表 | 主要信息 | 说明 |
| --- | --- | --- |
| `coinm_managed_positions` | `id,account_id,owner,symbol,position_side,contracts,entry_price,margin_asset,status,created_at,closed_at` | 一次持仓周期；同币再次开仓使用新 id |
| `coinm_managed_orders` | `id,position_id,client_order_id,exchange_order_id,account_id,symbol,position_side,intent,requested_contracts,filled_contracts,status` | 开/平/取消/部分成交均可精确关联；未成交 OPEN 的 position_id 可为空 |
| `coinm_trade_fills` | `account_id,symbol,order_id,trade_id,position_id,contracts,price,realized_pnl,pnl_asset,commission,commission_asset,trade_time,rest_verified` | 唯一键 `(account_id,symbol,order_id,trade_id)`；数量必须是张数 |

`delivery_symbols` 补最少量的交易规格及独立策略配置字段；只保存配置/交易所元数据，不用它代替持仓账本。实现使用数值精确类型，委托/成交/费用保存原始十进制，禁止浮点数影响结算。

**反向合约计算**（仅供校验）：多单的币本位理论毛 PnL 约为 `N × (1/E - 1/P)`，空单方向相反；`N = contracts × contractSize (USD)`。**实际已实现盈亏、手续费资产必须以 Binance DAPI 成交和结算记录为准**。资金费、手续费可能具有独立账单，不可只用名义价格差冒充完整净利润；证据不全展示 `incomplete`。

## 四、分阶段执行（与 02 独立验收）

| 阶段 | 实施工作 | 验收门槛 |
| --- | --- | --- |
| **C0：账户/规格审计** | 审核币本位 API、单向持仓、主账户凭据与 read-only/速率限制；核实 `contractSize`、交易精度、保证金资产；明确安全停止条件 | 不满足账户模式/规格即不能运行，形成只读审计结果 |
| **C1：DAPI 私有接口和持久结构** | 补下单、查单（含 client id）、撤单、`userTrades`、账户可用保证金/当前持仓；接入仅适用于 COINM 的凭据/限流/只读门禁；新增三张表和 Go migration | 全部 mock，可重启恢复，绝不误用 USDM/Spot API |
| **C2：按张数的策略执行和风控** | 从 `delivery_symbols` 读取自定义规则，剥离原 Futures 依赖；用合约乘数和实际 Binance 账户信息验证张数、预算、可用保证金、最大风险；保护开平仓归属 | 张数、USD 名义价值、结算币之间无混用；模式不符 fail-closed |
| **C3：真实 Fill/持仓周期** | 逐成交入 `coinm_trade_fills`、唯一 tradeId 去重、部分成交与部分平仓、撤单后补查、UNKNOWN 后按同 client id 恢复；保证平仓不超过受管理张数 | 开 10 张实成 4 张撤其余；平 1 后余 3，重复回放不改变持仓 |
| **C4：界面/回归** | 现有币本位模块增加配置和订单/仓位 tab，显示“张”“USD 名义”“保证金币”“真实手续费/PnL 币种”，日志、告警、中英文 README、构建与 mock 回归 | U 本位/Spot 零回归；真实交易默认 OFF |

**不做**：季度交割、自动开 Hedge Mode、跨账户资产转移、复杂清算引擎、全市场高频扫描、跨市场统一持仓、重写 USDM 订单逻辑。

## 五、必须覆盖的安全用例

1. `contractSize` 不存在、市场非永续、账户 Hedge/未授权、保证金币余额不足、精度不合法：全部拒单。
2. 开/平不同价格、分批成交、手续费以 BTC/其他币种结算、真实已实现盈亏负数；展示单位及收益口径准确。
3. WS/REST 若后续并存，重复 tradeId 只落一笔；断线/重启、部分撤单恢复无重复交易。
4. 本人手动持仓、USDM 同币、Spot 同币及另一 owner 的持仓不得被 COINM 认领/平掉。
5. 只在完成真实仓位归零及成交对账后结算；查询不完整要显示待核对，不能触发不可证实的亏损控制。
6. 模拟/测试、数据库事务失败、429、网络 UNKNOWN 下不会有重复下单；不开 DAPI 实盘也能完成所有自动化测试。

## 六、实施依赖和实际上线

- **开发衔接：[方案 02（Spot）S4](开发方案-02-S4-前端集成与完整验收.md) 完整验收之后开始本方案 C0**。两个市场是连续两大项，验收和账本相互独立；方案 04/05 的 U 本位双向持仓/加仓不构成 COIN-M One-way 首版的技术前置。

从 02 复用且仅复用以下已验证的小能力：现货独立策略求值/指标输入的纯接口设计、客户订单 ID 和状态转换的幂等规则、真实 tradeId 去重与补录测试用例、REST 限流/错误分类及模拟夹具。**不得复用 Spot 的 base/quote 库存计算、数据库表、手续费与 PnL 公式；也不引入跨市场 Broker 框架**。能按市场独立写清的部分留在 COINM 薄适配器。
- 方案 01 的**本地**真实成交规则可作设计参考，但其真实 Binance G1/G2/G3、生产性能与发布 G4～G6 尚未闭环；不能把这些旧证据标为已通过。
- COINM 实盘独立 Gate：官方 DAPI 只读查单/成交/持仓核实、单向模式、数量与保证金币、模拟异常/撤单/恢复、账户和订单作用域、生产 schema/双端发布、用户明确授权。未完成继续只读/Mock。
- 从实施时最新 Schema 版本递增（当前代码 v25；本方案 03 执行时再确定下一版本，不硬编码 v26）；只走 `./go_binance_futures sync db`，先 `go_bn_test`；不修改 `app.conf`、不擅改生产库、不发实单、不自动 commit/push。
