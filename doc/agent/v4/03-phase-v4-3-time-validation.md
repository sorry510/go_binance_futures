# Phase V4-3：Time Validation

## 目标

解决“策略只在某一段历史有效”的问题。

不建设复杂 Walk-Forward Optimizer，只做固定时间切片验证。

## 功能

对一个 Strategy Template + Symbol + 总时间范围，允许按固定窗口拆分为多个独立 Backtest Run。

首版支持：

- 按月。
- 按季度。
- 按半年。
- 自定义固定天数。

例如：

```text
2024-01 ~ 2024-06
2024-07 ~ 2024-12
2025-01 ~ 2025-06
2025-07 ~ 2025-12
```

每个窗口仍使用现有 Backtest Engine。

## 聚合指标

- 有交易窗口数。
- 盈利窗口数 / 亏损窗口数。
- 每窗口 Return。
- 每窗口 Max Drawdown。
- 每窗口 Profit Factor。
- 每窗口 Trade Count。
- 最差窗口。
- 无交易窗口数量。

重点观察策略是否只在单一行情阶段有效。

## 与 V4-2 的关系

V4-2 回答“跨币种是否稳定”。

V4-3 回答“跨时间是否稳定”。

两者保持简单分离，不建设统一复杂评分模型。

## 验收 Gate

- 切片边界明确，不重叠、不漏数据。
- 每个窗口可以单独打开原 Backtest 详情。
- 聚合指标与各 Run 可逐项对账。
- Listing 前区间继续使用现有 EarliestKline 边界处理。
- 不因为拆分窗口改变策略执行语义。

## 本阶段不做

- 不自动调参。
- 不使用前一窗口训练后一窗口。
- 不做机器学习训练集/测试集平台。
- 不做遗传算法式 Walk-Forward Optimization。
